## 3. 时间轴方案

### 3.1 七个问题的答案

**Q1 现在哪些日期字段可以直接用？**
`plannedStartDate`、`plannedDeliveryDate`（日历日期）、`startedAt`、`completedAt`、`cancelledAt`
（UTC 瞬时）、以及后端算好的 `deadlineState`。全部已在 `list_orders` 的返回里，**不需要新接口**。

**Q2 三个日期的语义分别是什么？**
- 计划开始：人工填写的排期意向，**不代表已经开工**，可以为空；
- 计划交付：人工填写的截止日，是 D-00-06 风险判定的唯一输入，可以为空；
- 实际开工：`work_started` 事件写入的瞬时；「撤销开工」会把它清空。
三者互不推算，不存在"没填计划开始就从开工时间倒推"这类规则。

**Q3 未排期 / 只有单侧日期 / 跨月怎么办？**

| 情况 | 画法 |
|---|---|
| 两个计划日期都空 | 不画轨道，保留现有「未排期」徽标（`deadlineState=unscheduled`） |
| 只有交付日 | 只画交付标记点，**不画区间**（画区间等于虚构开始日） |
| 只有开始日 | 只画开始标记点；徽标仍是「未排期」——因为 D-00-06 只看交付日，这是既有口径，不是缺陷 |
| 跨月 | 不做特殊处理：日历日期直接换算成"距今第几天"定位，跨月跨年都不会错（不用 24h 乘法，因此没有夏令时问题） |
| 已开工但未排期 | 画开工标记点，无区间 |

**Q4 活动 / 完成 / 取消 / 重开怎么处理？**

- 活动：轨道 + 交付标记，颜色取 `deadlineState`（逾期红 / 今天橙 / 三日内黄 / 未排期灰）；
- 完成：轨道转中性灰 + 完成标记，**不再用风险色**（后端对终态已强制 `scheduled`，不能凭空染红）；
- 取消：轨道虚线 + 取消标记，中性灰；
- 重开：`status` 回到 active，只画**当前这一轮**的 `startedAt`，不画历史轮次（历史在详情的事件流里）。

**Q5 怎么和搜索/筛选/手动排序共存？**
轨道是行内装饰，只读，不参与筛选与排序；搜索/筛选只决定"哪些行出现"，排序只决定"行在第几位"。
**刻度窗口固定（今天 ±45 天），不随筛选结果重算**——否则筛一下刻度就变，同一批订单的长短会失真。

**Q6 900px / 530px 怎么排才不重新造成重叠？**
轨道放在**现有 `.order-row-meta` 行的右侧**（`margin-left:auto`），不新增行高。
900px（容器 ≤780）保留轨道但限宽 `flex: 0 1 96px`；530px（容器 ≤560）**隐藏轨道**，
改在元信息里显示 `交付 11-20` 纯文本。这样 UI-06 好不容易换来的"一屏 3 行"不会被吃掉。

**Q7 会不会和长标题 Tooltip、键盘导航、滚动冲突？**
- Tooltip 挂在标题 `<span>` 上，轨道在另一行且 `aria-hidden`、无事件处理器 → 不抢指针；
- 轨道高度 ≤14px，不改变行高 → 键盘光标的 `scrollIntoView({block:"nearest"})` 逻辑不变；
- 轨道元素不加 `position: absolute`，避免与 `.order-row-cursor` 的负向 outline 打架。

### 3.2 首选方案 A：元信息行右侧迷你轨道

```text
┌──────────────────────────────────────────────┐
│ AF-2026-0003                        [制作中] │
│ 封面主视觉重绘与全彩上色…                    │
│ ● 制作中 · 线稿 · 王画家        ▮▮▮▮▪──┃     │
└──────────────────────────────────────────────┘
                                  ↑    ↑  ↑
                          计划开始  交付 今天
```

- 组件：`src/components/OrderScheduleBar.tsx`（纯展示，`aria-hidden`）
- 纯函数：`src/lib/scheduleBar.ts`
  - `localDay(instantIso, timeZone): string` —— 用 `Intl.DateTimeFormat('en-CA')` 取本地日历日；
  - `dayDiff(fromDate, toDate): number` —— 日历日差；
  - `buildWindow(today, days = 45): {from, to}` —— 固定 ±45 天；
  - `barModel(order, window, today)` → `{ leftPct, widthPct, markers: [{pct, kind, cls}], outliers: {left, right} }`
- 数据流：`OrdersPage` 已有 `orders` 与 `timezone`，`today` 取 `status.workingTimezone` 的当天；
  `barModel` 对每行算一次，`useMemo` 缓存；**不新增任何请求**。
- 超出窗口的日期：钳到边缘并加一个小箭头标记，具体日期进 `title`（原生 title 在这里可以接受：
  它不是 WKWebView 下 line-clamp 那个已知失效场景，但若验证不可靠，改用已有 Tooltip 组件）。

  风险色**复用现有 `--tone-danger/warn` 语义**，不新造一套。

复杂度：中低。新增 1 个组件 + 1 个 lib（含单测）+ 约 40 行 CSS，改 `OrdersPage` 一行 JSX。

### 3.3 备选方案 B：独立第三行的整宽轨道

```
│ 封面主视觉重绘与全彩上色…                     │
│ ● 制作中 · 线稿 · 王画家                      │
│ ├──────●━━━━━━━━━━━┃───────┤               │   ← 整宽 + 月份刻度
```

### 3.4 备选方案 C：纯文本区间

`交付 11-20 · 剩 3 天`（+ 3px 下划线条）。零风险，但信息量最少，只在 530px 与紧凑密度下作为降级形态使用。

**结论**：默认 A；≤560 容器自动降级为 C；B 不实现，除非 A 被判定不可用。

## 4. 图表数值与标签方案

### 4.1 现状（实测代码，不是印象）

| 问题 | 证据 |
|---|---|
| 数值只能靠悬停 | `StatsPage.tsx:193/198/203` 三根柱子只有 `title`，没有任何可见数值 |
| 没有坐标轴、没有刻度、没有网格线 | `.chart` 只有 `height:148px` + `overflow-x:auto`（`styles.css:1901`） |
| 零值看起来像"有值" | `.bar { min-height: 2px }`（`styles.css:1930`）——0 和 1 都至少 2px 高 |
| 浅色下两根柱子对比度不足 | `.bar-created #9fb6cb` ≈ **2.1:1**、`.bar-cancelled #d9b3a8` ≈ **1.9:1**（对白色面板），低于图形 3:1 |
| 深色下这两根反而正常 | 同一色对 `#182028` 约 8:1，所以问题是**只在浅色侧失败**，且是硬编码色，不受令牌控制 |
| 12 个月必然横向滚动 | 12×42px + 11×10px + 8px = **622px**，900px 窗口的内容区约 600px → 滚动条出现 |
| 屏幕阅读器拿不到数字 | `.chart` 是 `role="img"` + 一句 `aria-label`，没有数值；下方「月度明细」表有数字，但两者没有关联 |

### 4.2 改造方案（不引入图表库）

1. **令牌化三根柱子**：`--chart-created` / `--chart-completed` / `--chart-cancelled`，
   浅色取到对 `--surface` ≥ 3:1 的深度（约 `#5B7E9E` / `--accent` / `#B07A63` 一带，最终值按对比度算），
   深色沿用现有浅色系。这条必须**先于**其它改动，否则加多少标签都在读一根看不见的柱子。
2. **Y 轴 + 网格线**：左侧固定 3 个刻度（0 / 中值 / 最大值），网格线用 `--border`。
   轴要放在 `.chart` **外面**（`grid-template-columns: auto 1fr` 的 `.chart-frame`），
   因为 `.chart` 会横向滚动，轴跟着滚就等于没有轴。
3. **数值标签**：月份数 ≤ 6 时给每个非零值标 10px 数字；> 6 时只标每列的最大值（避免 36 个数字堆叠）。
   标签用 `font-variant-numeric: tabular-nums`，颜色 `--text-muted`，放在柱子正上方 2px。
4. **零值**：新增 `.bar-zero`（2px、`--border`、无圆角、不参与"有值"读感），并且**不标数字**；
   `title` 里明确写 `0`。全零区间继续用现有「这个区间内还没有任何事件」。
5. **大数字**：次数轴刻度用 `1k` 缩写（`compactCount()`），金额仍走 `yuan()`，**不碰金额格式与口径**。
6. **可访问性**：柱子列改为可聚焦（`tabindex=0`，`aria-label="2026-11：新建 10、完成 2、取消 1"`），
   hover 与 focus 都触发同一个数值气泡（复用 Tooltip 的 portal + fixed 做法，避免被 `.chart` 裁切）；
   `.chart` 的 `aria-label` 补上区间与合计，并注明"逐月数值见下方明细表"。
7. **小窗口**：530px 时列宽收到 34px、柱宽 6px、标签旋转或省略；横向滚动保留（12 个月塞不进 530px 是物理事实）。

### 4.3 明确不做

- 不引入 ECharts/Recharts/d3 等依赖（现有 CSS 柱状图足够，且体积/回归成本都高）。
- 不改「月度明细」表的任何一列。
- 不改 `statsApi` 返回结构。

## 6. 是否需要后端只读接口

**不需要。** 理由：

1. 时间轴要的日期字段 `list_orders` 已经全部返回（§1.2），且 `deadlineState` 已由后端算好；
2. 唯一的缺口是"UTC 瞬时 → 工作时区日历日"，这在前端用 `Intl.DateTimeFormat(timeZone)` 就能做，
   时区名 `status.workingTimezone` 也已经加载；
3. 一旦为了画图新增一个"按天聚合"的只读接口，就会引入第二套日期语义，
   与 `domain/deadline.rs` 的口径**很可能慢慢分叉**——这正是要避免的。

统计侧同理：`StatsReport` 已经含月份、三类次数、金额与"未知"计数，图表只是换呈现。
