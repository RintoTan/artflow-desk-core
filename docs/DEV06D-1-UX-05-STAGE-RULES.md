# 受控越级（阶段跳转）业务规则设计 — 待裁定

## 1. 现状（代码事实）

| 动作 | 行为 |
|---|---|
| `advance_stage` | 只能前进一步；要求 active + 已开工；写 `stage_advanced` 事件 |
| `rework_stage(target)` | 允许退回任意更早阶段（多阶段返工），不能前进 |
| 阶段存储 | `orders.current_stage_id` + `order_stages` 每单一份模板快照 |
| 事件 | `order_events` 记录 lifecycle，带 movement/时间戳 |
| 隔离 | 阶段 ID 属于订单自己的模板快照，跨模板不互通 |

**当前没有"向前跳多级"的合法动作。** 看板菜单对这类目标直接禁用。

## 2. 新旧行为对照

| 场景 | 现在 | 若增加越级 |
|---|---|---|
| 草稿 → 线稿 | 允许（advance） | 不变 |
| 草稿 → 固有色（跳过线稿） | **拒绝** | 允许，需新动作 |
| 固有色 → 草稿 | 允许（rework） | 不变 |
| 未开工订单改阶段 | 拒绝 | 仍拒绝（不绕过开工条件） |
| 已完成/已取消 | 拒绝 | 仍拒绝（终态走独立命令） |

## 3. 合法/非法矩阵（建议）

| 源状态 | 目标 | 允许 | 记录 |
|---|---|---|---|
| active + started | 前进 1 级 | ✅ advance | `stage_advanced` |
| active + started | 前进 ≥2 级 | ⚠️ 新增 `skip_stages` | `stage_skipped`（含 from/to/skipped[]） |
| active + started | 后退任意 | ✅ rework | 现有事件 |
| active 未开工 | 任意 | ❌ | — |
| completed/cancelled | 任意 | ❌ | — |
| 跨模板 | 任意 | ❌ | — |

## 4. 历史记录模型（建议）

- 新增事件类型 `stage_skipped`，字段：`from_stage_id`、`to_stage_id`、`skipped_stage_ids`、`reason`（可选文本）、`occurred_at`。
- **被跳过的阶段不生成完成时间**，也不标"已完成"；只在时间线里显示为"跳过"。
- 不修改既有事件的语义与历史数据；老订单没有该事件即为"从未越级"。

## 5. 数据迁移影响

- 需要新的 `order_events.kind` 允许值（或复用现有 kind + payload）。
- 若 `kind` 有 CHECK 约束 → 需一次迁移（v6）；若用 payload 则**无需迁移**。
- 建议：**先查 `order_events.kind` 是否有枚举约束**再决定是否迁移。本轮未执行任何迁移。

## 6. 测试方案（未来实施时）

1. 前进 1 级仍走 advance，不产生 skip 事件
2. 前进 3 级产生 1 条 skip 事件，skipped 列表正确
3. 被跳过阶段无完成时间
4. 跨模板跳转被拒
5. 未开工 / 终态被拒
6. revision 冲突无部分写入
7. 取消确认零写入
8. 历史订单时间线渲染不报错

## 7. 需要产品所有者裁定

1. 是否允许**向前**跳多级？（向后已允许）
2. 是否要求填写跳转原因？
3. 被跳过阶段在时间线上如何呈现（隐藏 / 显示为"跳过"）？
4. 是否允许跳到"最后一个制作阶段"（即跳过所有中间阶段）？
5. 越级是否需要独立的撤销动作？
6. 是否接受新增 `stage_skipped` 事件类型（会影响 CSV 事件导出列）？
