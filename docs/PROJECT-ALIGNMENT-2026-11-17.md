## C. 需求遗漏与范围差异清单

### C.1 文件拖拽导入（`REMAINING-WORK #8`）

**核实结果：完全未实现。** 全仓 `rg "dragDrop|onDrop|onDragOver|tauri://drag"` **零命中**；
`tauri.conf.json` 也没有配置 `dragDropEnabled`。现有导入只有一条路径：`attachment_import`
（系统文件选择器 → 后端校验 → 入库）。

- 普通导入与拖拽**没有**共用验证的问题——因为拖拽那条路根本不存在；
- 也不会影响列表排序：列表的拖拽是自实现的 pointer 事件（`OrdersPage.drag.test.tsx`），
  与操作系统文件拖放是两套机制；
- 多文件导入：`attachment_import` 支持多选，逐项结果由前端汇总（已有测试）。

**建议**：放 **DEV-07-FINISH**。理由：它需要重新打开 Tauri 的 window drag-drop 事件通道
（`dragDropEnabled: true` 会抢占 HTML5 拖放，与列表排序的 pointer 实现虽不冲突，但要实测），
属于"附件体验收尾"，与 DEV-08 打包前必须做完；放在备份恢复之前会打乱 DEV-07 的风险面。

### C.2 Asset 协议运行时安全

- 配置层：正式 `$APPDATA/generations/*/attachments/**`，QA 额外包含 `seeded` / `clean` 两个子树；
- 代码层：`attachment_*` 命令都做路径发布守卫（只返回 generation 内的相对路径），
  后端有 `tests/asset_scope.rs` 覆盖路径规范化与越界；
- **缺**：真实 WKWebView 运行时用构造 URL 访问目录外文件的负向验证（`REMAINING-WORK #9`）。

**状态**：配置 + 单元测试 PASS，运行时 **NOT VERIFIED**。
**建议**：列为 **DEV-08 安全验收的前置条件**（打包版才有真实 custom protocol 行为）。

### C.3 `attachments/quarantine/` 长期清理

- 产生场景：`domain/attachments.rs:298 move_to_quarantine()`，在清理任务发现
  "文件已存在但数据库无引用"或"引用缺失"时把可疑文件移入隔离区；
- 用途：异常恢复时人工比对，**不自动删除**；
- 现状：**只增不减，没有任何清理入口**（命令面无相关项）。

**风险**：长期累积占磁盘；但误删会丢掉唯一可恢复副本。
**建议**：随 **DEV-07** 的数据维护做"手动清理 + 先展示占用与清单"，
不实现自动清空（本轮也不实现）。

### C.4 `attachment_jobs` 已完成记录

- 表在 schema v3，索引 `(state, kind)`；`pending` 行在恢复时被消费；
- **全仓没有 `DELETE FROM attachment_jobs`**——完成的作业行永久保留；
- 正式库当前 1 行（`done`）。每次导入/校验/修复各留一行。

**诊断价值**：能看出"某次导入做到哪一步"，崩溃恢复靠它。
**最小方案**：DEV-07 里加"保留最近 N 天 / N 条"的手动清理命令，默认不执行；
不引入自动过期，避免把崩溃现场一起删掉。
