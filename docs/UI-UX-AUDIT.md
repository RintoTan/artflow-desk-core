## P0

### P0-1 未知路由直接抛英文开发者错误页

- 位置：任意未匹配路由（例如 `/dashboard`）。截图：本轮误用该路由时得到的
  `Unexpected Application Error! 404 Not Found / Hey developer 👋`。
- 问题：React Router 默认错误页，英文、面向开发者，暴露内部措辞。
- 影响：用户误入或深链失效时看到"程序出错"，会怀疑数据损坏。
- 建议：加 `errorElement`，中文文案 + "返回工作台"；404 与运行期异常分开。
- 组件：`src/main.tsx` 路由表。
- 回归风险：低（新增兜底分支）。

### P0-2 深链/刷新后的错误页与数据状态不对等

- 同上一条同源。刷新丢失上下文时若命中错误页，用户无法判断数据是否完好。
- 建议与 P0-1 合并处理。

## P1

### P1-1 卡片视图在中窄窗口下堆叠，列表下方留大片空白

- 位置：订单页 900px（截图 `dev06d-1-ux/cards-900.png`）。
- 问题：容器查询把双栏切成上下堆叠后，列表容器仍保留固定高度，
  3 条订单下方留下约 100px 空白，再下面才是详情。视觉上像"列表没加载完"。
- 影响：中窄窗口下首屏信息密度下降，用户要多滚动一次才能看到详情。
- 建议：堆叠时列表高度改为 `max-content`（受上下限约束），或把"固定高度"只在双栏时生效。
- 组件：`.orders-list` / `.order-rows` 的容器查询块。
- 回归风险：**中**，DEV-06B 的行高与可见行数门禁依赖这个高度，改前需重跑几何检查。

### P1-2 空的阶段列没有明显可放置提示

- 位置：看板（`board-900.png` 右侧"细化"列）。
- 现状：空列有"拖到这里"，但样式很淡，与卡片视觉权重差太多。
- 建议：空列给出更高的虚线落区高度（最小 80px），拖拽经过时才高亮。
- 组件：`.board-col` / `.board-empty`。
- 回归风险：低。

### P1-3 抽屉与确认框的层级关系未定义

- 位置：看板 → 打开详情抽屉 → 在抽屉外的看板操作。
- 问题：抽屉不是模态，确认框是模态；两者同时存在时 Esc 归属需要明确规则。
- 建议：抽屉打开时，看板拖拽禁用（或抽屉收窄为只读摘要）；Esc 优先关栈顶模态。
- 回归风险：中（涉及 `modalStack` 语义）。

### P1-4 表格视图列数多，窄窗只能看到前 4 列且无滚动提示

- 位置：`table-880.png`。
- 现状：容器内横向滚动可用，但没有任何"还有更多列"的提示。
- 建议：右侧加渐隐遮罩或"横向滚动查看更多"的一次性提示。
- 回归风险：低。

## P2

### P2-1 订单页头部的"数量摘要"文案两处不一致

- 卡片视图写 `4/4 张 · 活动在前`，宽视图写 `4/4 张 · 与卡片视图同一份数据与筛选`。
- 建议统一为 `4/4 张 · 活动在前`，把"同一份数据"的说明移到提示行。
- 风险：低。

### P2-2 QA 横幅已经压到一行，但仍是"最显眼的元素"

- 位置：所有页面顶部。
- 现状：橙色边框 + 橙色文字，视觉权重高于页面标题。
- 建议：改为左侧细色条 + 中性底色，保留文字与色彩信号但降低边框重量。
- 风险：低（只要保留"QA / 隔离"两个关键词）。

### P2-3 客户页左侧列表与右侧详情的信息重复

- 位置：`clients-900.png`。列表已显示 `N 单 · 活动中 N`，详情又有"客户概览"三项。
- 建议：列表只保留名称与标签，统计只在详情出现。
- 风险：低。

### P2-4 客户页"管理全部标签"用了 `<details>`，与其它面板的展开样式不一致

- 建议：换成与模板页一致的可折叠区块。
- 风险：低。

### P2-5 统计页与订单页的筛选控件高度不统一（`34px` vs 自适应）

- 建议：统一 `.select-inline` 与 `.filter-chip` 的高度令牌。
- 风险：低。

### P2-6 设置页的分节间距明显大于其它页面

- 位置：`settings-900.png`。
- 建议：统一 `section` 间距令牌。
- 风险：低。

### P2-7 空状态多为一行纯文字，缺少下一步动作

- 位置：订单页/客户页/模板页空态。
- 建议：空态给出主操作按钮（新建订单 / 新建客户）。
- 风险：低。
