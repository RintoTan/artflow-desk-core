## 三、Schema 演进

| 版本 | 引入 | 为什么需要新版本而不是改旧迁移 |
| --- | --- | --- |
| v1 | 客户、模板、订单、订单阶段、生命周期事件、附件、清理任务、主题、设置 | 初始业务库 |
| v2 | 队列版本、订单说明、事件幂等键、阶段重名约束 | 并发与幂等 |
| v3 | 附件操作日志 | 文件系统与 SQLite 无跨介质事务，先记「打算做什么」 |
| v4 | 订单来源、作品分类与展示状态、客户标签 | 三组变更合并为一步，失败整步回滚 |
| v5 | 「可展示 ⇒ 必须成品」下沉为触发器 | v4 已落入部分 QA 代际，改 v4 会让新库与旧库分叉 |

| v7 | `order_events` 支持阶段跳级（含被跳阶段快照） | 同上 |
| v8 | 软删除两列 + 两个部分索引 + 三个可见性视图 | 删除是可见性，不是业务状态 |

## 四、v0.1.2 发布过程（三轮资产替换）

| 轮次 | 触发 | 结果 |
| --- | --- | --- |
| 1 | 首次发布，tag `1935fb0` | macOS zip 缺 `_CodeSignature`（`bundle.macOS` 没有 `signingIdentity`，`tauri build` 只留下 linker-signed 的二进制），用户机器上报「已损坏」，右键打开也救不回来 |
| 2 | `2626f3b` 补 `"signingIdentity": "-"` | 重打 macOS 包，`codesign --verify --deep --strict` 通过；Gatekeeper 恢复为「无法验证开发者」，右键「打开」可用。Windows 首轮 CI 产物同时上传 |
| 3 | `41a41b4` 修「已完成/已取消订单插进手动队列」+ 截图补拍 | 重打三件产物并覆盖上传；当前哈希见 [PROJECT-STATUS §三之九](../releases/PROJECT-STATUS.md)。**这次修复晚于 Tag**，所以最终安装包与 `v0.1.2` 指向的 `1935fb0` 不是同一源码快照 |

第三轮之后的两次补修（客户搜索框样式、客户页财务概览两列、看板默认全部流程）已包含在第二轮重建里，属于发布前修复，不再单独发版。

**证据边界**：Windows 产物只经过 GitHub Actions 原生 `windows-latest` 构建 + Runner 上两轮启停冒烟（11 项检查 0 失败），**没有在实体 Windows 机器上安装使用过**。macOS 三件产物构建成功、签名可校验，**正式包从未启动过**（启动会迁移生产数据根）。

## 五、被撤回或被否决的方案

| 方案 | 结局 | 原因 |
| --- | --- | --- |
| 统计页吸顶页头（`position: sticky` + 收紧态 + 背板 + 滚动监听） | **撤回**。只存在于工作区，未产生独立提交；撤回发生在 `82229bb` 之前，`52167af` 清掉了配套素材 | 产品负责人实际试用后否决。保留页面级共用页头、切视图回顶与统计口径 |
| 在 macOS 上交叉编译 Windows | **放弃**，改用 GitHub Actions `windows-latest` | 卡在缺 `llvm-rc` / `llvm-lib`，补齐工具链成本高于收益 |
| 看板按阶段分列 / 聚焦模式 | **改为扁平总览**（`d6c6861`） | 列把「阶段」和「排序」两套维度搅在一起，实际操作更慢；0.1.2 只调默认筛选与排序，不动结构 |
| 客户参考图混进 `attachments` 表（加 `client_id`） | **否决**，v14 独立建表 | 两种归属混进同一主键空间；订单删除时客户图不该跟着消失 |
| 先把废弃订单永久删除再备份以控体积 | **否决** | 破坏「历史不可改写」，误删也无法从备份找回 |
| 时间线「同月堆叠 4 行 + 超出合并 +N」 | **未实现并冻结** | 与现有「每单一行」行模型冲突，需先出按月聚类的视觉原型 |
| 登录后默认页面、自动定时备份、备份加密、旧代际清理入口 | **冻结** | 与本地优先、无常驻后台的取向冲突，或涉及密钥管理 |
