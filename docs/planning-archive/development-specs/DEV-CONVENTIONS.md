# 开发规范

## 1. 分层

```text
src-tauri/src/
  commands/   薄壳：参数校验 + 调用领域服务，不写 SQL
  domain/     业务规则（编号、订单、流程……）
  store/      持久化：环境、代际、迁移、设置、时区、高水位、诊断
  media/      附件路径与资源限制
  backup/     备份包读取与安全校验
  infra/      跨进程锁、进程状态
  lib.rs      只做装配
```

三条硬规则：

1. **命令层不写 SQL，`lib.rs` 不写 SQL。** 有测试守着（`tests/commands.rs`）。
2. **每个写操作一个事务。** 用 `BEGIN IMMEDIATE`，并用受影响行数判断是否真的写成功；
   不得把失败报告成成功。
3. **命令白名单独立维护。** 新增命令必须同时改 `tests/commands.rs` 的 `APPROVED`
   与 `capabilities/default.json`，否则测试失败。

## 2. 数据与代际

- 业务数据只存在于当前活动代的 `database.sqlite`。**不允许出现第二套可独立修改订单的库。**
- 代际切换只能通过 `state/active.json` 的原子替换完成。
- schema 升级在**新代际**中进行：复制 → 迁移 → 校验 → 切指针。失败保留旧代际。
- 清理旧代际只能在文件身份、活动引用、回退需求、锁一致性全部确认后进行；
  不允许"按创建时间删到只剩 N 个"。

## 3. 编号

- 展示编号 `AF-YYYY-NNNN`，内部 ID 独立。
- 高水位存放在 `state/highwater.sqlite`，**在业务代际之外**。
- 顺序：先持久保留编号 → 再创建订单。两者没有跨文件事务，
  因此允许跳号，绝不允许复用。
- 绝不通过 `SELECT MAX(code)` 求下一个编号。
- 恢复备份时逐年取 `max(本机, 备份)`，高水位只升不降。

## 4. 时间

- 事件时间戳：UTC RFC3339，毫秒精度，`Z` 结尾。
- 计划日期：`YYYY-MM-DD` 日历日期，不带时区。
- 工作时区：IANA 名称，持久化在 `app_settings.working_timezone`。
  修改时区不改变已保存的时间点，只改变展示、提醒与统计月份归属。
- 订单编号的年份在创建时按当时的工作时区确定并固定。

## 5. 附件

- 原图与缩略图分离，缩略图是可重建的缓存。
- 落盘路径必须是代际目录内的 **ASCII 相对路径**；禁止盘符、绝对路径、反斜杠、`..`。
- 单文件上限 100 MB，并限制单边像素与总像素。
- 删除文件前必须确认没有其他有效引用，并校验目标仍在数据目录内。

## 6. 错误

`AppError { code, message }`。前端只按 `code` 分支：

| code | 含义 |
|---|---|
| `INVALID` | 输入不合法 |
| `CONFLICT` | 并发冲突（revision 不匹配） |
| `NOT_FOUND` | 目标不存在 |
| `DENIED` | 越界访问被拒绝 |
| `BUSY` | 另一个进程持有锁 / 已有操作在进行 |
| `DB` / `IO` | 底层失败 |
| `ZIP` | 备份包校验失败 |
| `SCHEMA` | 结构版本不兼容 |
| `ENV` | 数据环境异常（拒绝自动建库） |
| `NUMBERING` | 编号记录不可用 |
| `TIMEZONE` | 时区非法 |

## 7. 测试

- 涉及安全与数据完整性的机制必须有测试，且不得用"数量"代替"质量"。
- 跨进程行为必须用**真实子进程**验证（`src/bin/minidesk_probe.rs`），不用线程模拟。
- 崩溃行为必须用真实 `abort()`，不能用"返回错误"冒充。
- 未实现的功能不得写空断言凑数。
- 测试只用虚构数据，且全部在 `tempfile` 临时目录内，不触碰用户数据目录。

## 8. Git

- 一项独立任务对应一个可追溯的提交；通过测试后再提交。
- 不把无关的依赖升级混进业务提交。
- 不自动推送远程仓库。
