## 6. 是否需要数据库迁移

**结论：不需要。**

| 统计数据 | 来源 | 现状 |
|---|---|---|
| 新建次数 | `order_events(kind='created')` | 已有 |
| 完成/取消次数 | `order_events(kind in ('completed','cancelled'))` | 已有 |
| 金额汇总（按创建月归属） | `orders.created_at` + `orders.amount_cents` | 已有 |
| 活动/排队/制作中 | `orders.status` + `orders.started_at` | 已有 |
| 到期/今天/逾期/未排期 | `orders.planned_delivery_date` + `status` | 已有 |
| 本月完成事件明细、跳转订单 | `order_events` + `orders` | 已有 |
| CSV 明细字段 | `orders` + `clients.display_name` | 已有 |

唯一可能需要斟酌的是**索引**：按 `occurred_at` 范围扫 `order_events` 目前走
`order_events_kind_idx(kind, occurred_at)`，对"某 kind 在某区间"是合适的；
"某区间所有 kind"则会退化为全表扫。当前数据量（单画师）下无需优化，
**不建议为了性能预估加迁移**。如果 DEV-05 实测有慢查询，再单独评估。

按 DEV-01 立的规矩：**能不改结构就不改**，避免触发用户数据的代际迁移。
