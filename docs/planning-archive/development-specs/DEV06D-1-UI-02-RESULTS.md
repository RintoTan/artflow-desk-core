## 4. 选用的方案与理由

**共享页头 + 工作区分层**：`.orders-page`（flex 列）→ `.orders-head`（面板）+ `.orders-layout`（网格）。

- 页头只渲染一份，三个视图共用 → 切换按钮位置固定，不再各自一套页头。
- 卡片视图的工作区仍是 `320px + 1fr`；看板/表格为单列，占满宽度。
- 没有用 `position: fixed` 强行钉住工具区。

**看板**：保留横向 Kanban（方案 A），**补阶段导航**：顶部一排阶段胶囊（含每列数量）+ `‹ ›` 步进按钮，点击滚动到对应列；滚动时用 `scroll` 事件同步"当前位置"。理由：列宽 200–260px 是阅读下限，880px 窗口塞 5 列必然不可读，所以问题不在"有滚动"，而在"看不见还有哪些阶段"。

**表格**：按信息优先级分两级。核心列（编号/客户/标题/来源/阶段/状态/计划交付/金额）始终显示；次要列（类型/排期）在窄容器（`@container max-width: 720px`）收起，进详情看。表格宽度改为 `max-content`，核心列 `white-space: nowrap`，标题单独允许换行并截断。

## 10. 交互与可访问性

- 视图切换：`aria-pressed` 标记当前视图；三视图位置一致由几何断言守住。
- 看板：拖拽 + `→ 下一阶段` 按钮 + 确认框（`ConfirmDialog`，焦点进入/环/Esc/还原）。
- 表格：行 `tabIndex=0`，Enter/空格打开详情。
- 单一 `h1`：详情标题为 h1，页头为 h2（此前两处 h1 已修正）。
- 切换不动业务字段：几何门禁读取 `window.__MINIDESK_CALLS__`，业务写入计数 0。
