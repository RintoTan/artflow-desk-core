## 3. 看板拖拽根因（已修，未实机验证）

两个 WebKit 不兼容点：

1. 卡片正面是 `<button>`，WebKit **不会**从表单控件起拖 → `dragstart` 不触发（Blink 允许，所以此前无头验证一直通过）。
2. `dataTransfer` 用自定义 MIME `text/minidesk-order`，WebKit 读回空串。

修复：新增独立拖拽柄 `.board-card-grip`（`div`，`draggable`），数据改 `text/plain` + `minidesk-order:` 前缀，保留 `dragging` 状态兜底，目标列补 `onDragEnter` 高亮。业务动作、revision 校验、二次确认全部未变。

**归类：A（事件未触发）+ B（id 读不到）；不是 C/D。状态：待 QA-02 实机确认。**

## 4. 看板：聚焦式（方案 B）

- 顶部阶段导航列出**全部**阶段与数量（实测 5 项），点击/`‹ ›` 切换聚焦位置。
- 主体按实测宽度渲染 1–3 列：530px → 1 列；900px → 2 列；1400px → 3 列；列宽 `flex: 1 1 200px`，上限 300px。
- 窄窗不再需要横向滚动（几何断言：`scrollW ≤ clientW + 2`）。
- 拖放目标：合法目标始终在视野内；落到某列仍按**目标订单自身模板**解析阶段 ID，跨模板、跨阶段、未开工、终态照旧拒绝。
- `→ 下一阶段` 按钮保留，作为键盘可达的完整路径。

## 5. 表格：自适应两形态

- `< 760px`：四列——`编号` / `委托(标题 + 客户·来源)` / `阶段(+状态)` / `交付(+金额·风险)`，无横向滚动。
- `≥ 760px`：完整十列（含类型、排期）。
- 编号/日期/金额全部 `nowrap`，标题可查看全文；排序只影响展示；点击打开同一抽屉；不含任何收款字段。

## 6. 页头两级

一级：标题 + 数量 · 三视图切换 · 新建。二级：搜索 · 来源 · 状态胶囊 · 密度 · 导出（靠右）。

页头仍是三视图共用的单一节点，切换视图时 `x/y/width` 完全一致（几何断言保持）。

## 7. 抽屉

- 新增 sticky `.drawer-bar`：标题「订单详情」+ 32×32 关闭按钮（描边叉号，`currentColor`），hover/focus 有状态，Esc 可用，脏草稿阻止静默关闭。
- 顺带修掉：点"已选中的卡片"以前无反应（`attemptSelect` 提前 return），导致抽屉打不开。现改为重新打开抽屉。

## 8. 底部安全距离

`.order-rows` / `.board-cards` / `.table-wrap` 各 22px，`.orders-detail` 34px。实测值由断言读取 `padding-bottom` 校验 ≥20px。

## 9. 键盘 / 焦点 / 滚动

- Tab：视图切换 → 搜索 → 来源 → 状态胶囊 → 密度/导出 → 卡片/行 → 抽屉关闭。
- Enter/空格：卡片、表格行打开详情；`→ 下一阶段` 打开确认框。
- Esc：关确认框（栈顶优先）、关抽屉（脏草稿时改为提示）。
- 看板：`‹ ›` 与阶段胶囊均为原生按钮，可键盘操作。
