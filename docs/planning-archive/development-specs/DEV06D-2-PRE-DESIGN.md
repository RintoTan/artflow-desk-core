## 2. 产品目标与状态矩阵

只读甘特：不做日期拖拽、不算完成进度、不补日期、不新建排期数据。

### 2.1 功能矩阵

| 功能 | 行为 |
|---|---|
| 订单信息列 | 编号（等宽数字）/ 标题（单行省略，title 提示全文）/ 客户 · 阶段 · 金额 |
| 顶部双层刻度 | 日/周：上层月、下层日或周起始；月：上层年、下层月；年：上层年、下层季度 |
| 四种尺度 | 见 §4.2 窗口与像素 |
| 定位今天 | 把今天滚到视口 45% 处；`prefers-reduced-motion` 时不做平滑滚动 |
| 今天虚线 | 1px 虚线，跨表头以下全高；表头里有一个「今天」小旗 |
| 排期条 | 复用 `barModel`：有区间画条；只有一端画点 + 标记；反向区间只画两点 |
| 终态订单 | 默认隐藏；打开「显示已结束」后以虚线中性条显示，不参与风险着色 |
| 未排期订单 | 不进时间线，列在下方「未排期（N）」区，可点进详情补日期 |
| 横向滚动 | 单一滚动容器，表头 `sticky top`，信息列 `sticky left`；两者共用同一 x 坐标，不做 JS 同步 |
| 点击进详情 | 行信息列与条形都可点，跳 `/orders?orderId=<id>`；键盘 Tab + Enter 同样可用 |
| 空状态 | 一个已排期订单都没有时，显示「当前范围内没有已排期的订单」，未排期区仍在 |
| 加载失败 | 独立错误面板 + 重试按钮，不回退到示例数据 |
| 日期异常 | `parseDayKey` 判非法即视为「没有该日期」；两端都非法 → 未排期，不猜 |

### 2.2 状态矩阵（行 × 排期）

| 订单状态 | 有计划开始 + 交付 | 只有交付 | 只有开始 | 两者都没有 | 反向区间 |
|---|---|---|---|---|---|
| active | 实心条 + 双标记，按 `deadlineState` 着色 | 条纹条（仅交付），交付标记着色 | 起点圆点 + 「仅开始」标签 | 未排期区 | 不画条，两个点 + 「日期顺序异常」 |
| complete / cancelled | 虚线中性条 + 中性标记（默认隐藏） | 同左 | 同左 | 未排期区（终态一般不列出） | 同左 |

窗口外：不把条形挪到边缘，改为行内提示「窗口外：YYYY-MM-DD → YYYY-MM-DD」。

## 4. 算法规格

### 4.1 日期

- `parseDayKey`：正则 + 回读校验；`2026-02-30`、`2026-13-01`、`2026-1-1` 一律 `null`。
- 闰年：由 `civilFromDays` 反解，不写 365/366 分支。
- 工作时区：计划日期是日历日，**不做时区换算**；只有 `startedAt/completedAt/cancelledAt` 这类瞬时用 `localDayIndex`。
- 「今天」：`localDayIndex(new Date().toISOString(), workingTimezone)`；每 60s 与窗口 focus 时重算，跨午夜自动迁移。

### 4.2 尺度窗口与像素（设计基准）

| 尺度 | 窗口 | px/天 | 单日条最小宽 | 说明 |
|---|---|---|---|---|
| 日 | 今天 −7 … +13（21 天） | 44 | 30px | 适合看这一周多的交付 |
| 周 | 今天 −3 周 … +8 周（78 天） | 26 | 18px | **默认尺度**；周一起算 |
| 月 | 今天 −2 月 … +10 月（约 366 天） | 6 | 8px | 月刻度；跨年时上层按年分组 |
| 年 | 今天 −1 年 … +4 年（1826 天） | 1.8 | 3px | 季度刻度；单日条退化为点 |

窗口随「今天」滑动，不随筛选变化（所有行同一坐标系）。

### 4.3 条形几何

```
start = parseDayKey(plannedStartDate)
due   = parseDayKey(plannedDeliveryDate)
bandStart = start ?? (due - DEFAULT_DELIVERY_SPAN=7)
bandEnd   = due   ?? (start + MIN_START_SPAN=2)
left  = clamp(dayToX(max(bandStart, window.from)))
right = clamp(dayToX(min(bandEnd, window.to)))
width = max(right - left, MIN_BAR_WIDTH[scale])
```
- 只有交付：从交付日往前 7 天画条纹条，明确是「推定展示」而非计划开始（图例写明「仅交付日期」）。
- 只有开始：从开始日往后 2 天的短条 + 起点标记。
- 反向区间：`due < start` → 不画条。
- 越界：整段在窗口外 → 行内提示，不钳到边缘。
- 风险色只读 `order.deadlineState`；终态一律中性。

### 4.4 刻度与坐标系

- 唯一映射 `x = (day - window.from) * pxPerDay`；表头、条、今天线都用它。
- 刻度生成：日→逐日；周→每周一；月→每月 1 日（上层按年分组）；年→每年 1 月 1 日（下层季度）。
- 表头与内容在同一个横向滚动容器内，`sticky` 只负责吸附，不参与坐标计算。

### 4.5 今天线与滚动

`todayX = x(today) + pxPerDay/2`。定位按钮滚到 `todayX - 视口宽 × 0.45`；首次进入同样居中今天。

### 4.6 性能

- 只对 `window` 内的日期生成刻度（最多 1826 天 → 1826 个 tick 在年尺度会太多，年尺度按季度聚合，实际 ≤ 24 个）。
- 行渲染：`content-visibility: auto` + `contain-intrinsic-size: 58px`，200 行内不做虚拟化；超过 200 行再引入窗口化（写在风险里）。
- 数据变化：`listOrders()` 返回后一次性计算行几何；切换尺度只重算几何，不重新请求。

### 4.7 刷新

进入工作台、窗口 focus、点击「刷新」时重新拉取；不做轮询。订单在其它页面被修改后，返回工作台即重取。

## 5. 响应式

断点按**时间线容器宽度**（`container-type: inline-size`），不看窗口。

| 容器宽 | 信息列 | 默认尺度 | 行为 |
|---|---|---|---|
| ≥ 1100 | 320px | 周 | 图例单行；刻度完整 |
| 760–1099 | 260px | 周 | 图例换行；标题两行截断 |
| < 760 | 200px | 月 | 隐藏「客户 · 金额」，只留编号 + 标题；图例收成「图例」按钮 |

- 900px 窗口：内容区约 585px → 走 <760 分支，默认月尺度，减少横向滚动需求；用户仍可切日/周。
- 1680px：信息列 320px，剩余全部给时间线；行高 58px，一屏可看 9–10 单。
- 矮窗口（400px 高）：`max-height: calc(100vh - 210px)`，表头保持 sticky，未排期区随页面滚动。

## 9. 实施拆分与风险

| 步骤 | 内容 | 产出 |
|---|---|---|
| 1 | `lib/timeline.ts` + 单测（窗口/刻度/几何） | 纯函数层，无 UI |
| 2 | `ProjectTimeline` 静态渲染 + 图例 + 空态 | 只读面板 |
| 3 | 尺度切换 + 定位今天 + 终态过滤 | 交互完整 |
| 4 | 行点击/键盘 + 响应式 + 深色 | 可验收 |
| 5 | 布局检查与性能抽样 | 回归证据 |

**风险**

1. 年尺度信息密度低：1826 天在 3287px 内，单日条只有 1.8px。缓解：季度刻度 + 最小时长点；是否需要「年尺度隐藏单日条，只画聚合区间」待产品裁定。
2. 200 行以上未虚拟化：先用 `content-visibility` 顶，超过阈值再加窗口化。
3. 只有交付日期的 7 天推定条可能被误读为计划开始。缓解：条纹纹样 + 图例 + 行内「仅交付日期」。
4. 表头 sticky 与信息列 sticky 叠加，在 WKWebView 旧版本可能有 1px 缝隙，需要实机确认。
5. 工作台当前只有 `statsApi.dashboard()`；新增订单读取会让首屏多一次 IPC。缓解：并行、独立错误边界。
