# 产品概览

## 一句话

给独立画师用的本地委托台账：接单、排期、画到哪一步、什么时候交付，都在一个地方。

## 目标用户

- 独立接单的画师（个人，或一到两人的小工作室）。
- 委托来源分散在私信、邮件、平台站内信，靠记忆和聊天记录管理容易漏单。
- 不愿意把客户信息放到云端服务里。

## 解决的问题

| 痛点 | 现在的做法 |
| --- | --- |
| 单子多了记不清进度 | 一笔订单一条记录，阶段推进留痕 |
| 客户改期后对不上 | 计划日期与改期历史分开记录，实际完成时间来自事件 |
| 参考图散落在聊天窗口 | 附件挂在订单上，原图与缩略图本地保存 |
| 换电脑怕丢数据 | 整库 + 附件的备份包，可整体迁移 |

## 核心业务流程

```
建客户 → 建订单（按模板生成阶段副本，分配编号） → 排计划日期
      → 开工 → 逐阶段推进（可返工 / 可跳级） → 完成或取消
      → 按月统计（完成数、收入） → 导出备份以便迁移
```

三条贯穿规则：

- **计划日期与事件时间分离**：排期是日历日期，实际发生时间只来自事件；
- **历史不可改写**：事件存阶段名称快照，改模板不影响已有订单；
- **编号单调只增**：恢复旧备份也不会让编号倒退。

## 功能体系

| 模块 | 能力 |
| --- | --- |
| 工作台 | 进行中/排队中/制作中计数；三日内到期、今天到期、已逾期提醒；本月完成次数；跨订单项目时间线（日/周/月/年尺度） |
| 订单 | 卡片 / 看板 / 表格三视图；新建、编辑、复制、取消、完成、重开；队列排序；阶段推进、返工、受控跳级；完整制作历史；搜索 |
| 客户 | 客户资料与标签；关联订单下钻；同名不合并 |
| 流程模板 | 自定义阶段模板；新订单按模板生成自己的阶段副本；系统保留一个默认模板 |
| 日历 | 月 / 周视图；按计划起止日期铺排；拖放改期；连续滚动；改期写入历史 |
| 历史统计 | 月度完成与收入；客户 / 模板维度下钻；按当前筛选导出 CSV |
| 附件 | 多选与拖拽导入；缩略图与原图预览；隔离文件与导入记录手动维护；缩略图可重建 |
| 备份与恢复 | 整库快照 + 附件 + 校验清单打包 ZIP；恢复前自动快照；隔离代际恢复 |
| 设置 | 主题（浅色/深色/跟随系统）、强调色、应用图标、工作时区、备份与附件维护 |
| 关于软件 | 版本、归属、数据环境、使用指引 |

## 能力边界

**做**：单机、单画师、本地数据、可迁移、可备份恢复。

**不做**（截至 v0.1.0-demo.2）：云同步、多设备同步、多用户权限、客户自助页面、在线支付、画廊/作品集、自动定时备份、备份加密、旧代际清理入口、永久删除与回收站。完整清单与理由见 [PRODUCT-DECISIONS.md](PRODUCT-DECISIONS.md)。

> 本节为 v0.1.0-demo.2 时期的产品范围快照；其中「永久删除与回收站」已在 v0.1.1 交付，后续变化以 [PROJECT-STATUS.md](../releases/PROJECT-STATUS.md) 为准。

**部分实现**：

- **订单「复制」已实现**（ORDER-01）：复制资料与流程快照，重置进度与排期；附件默认复制为独立文件副本，可取消。
- 收入统计只有「创建月归属」口径；按完成月归属尚未提供。
- 跨平台备份仅验证单向（macOS 生成 → Windows 恢复）。
- 附件逐张预览已在自动化层覆盖，真机未逐项走查；拖拽跟手观感未验证。

未实现的内容不得当作现有功能宣传。

## 与 Web 版的关系

ArtFlow Desk（Web）与 ArtFlow Desk Core（桌面）同属 ArtFlow Desk 产品体系，但：

- 代码库独立；
- 数据独立，不共享数据库；
- 发布独立。

两者不是同一个应用的两个入口。
