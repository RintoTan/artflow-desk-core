| 能力 | 实现要点 |
| --- | --- |
| 业务数据包 | 快照 → 新代际（v9）→ 按需回填 → `integrity_check` + `foreign_key_check` → 原子切 `active.json`；旧代际保留 |
| 用户设置 | 就地事务：清偏好键、恢复默认、删自定义主题、保留内置主题 |
| 备份 / 提醒 / 日志 / 隔离区 | 各自独立执行，逐项报告 |
| 硬白名单 | `environment.json` / `.write.lock` / `active.json` / `highwater.sqlite` / `recovery/` 在 Rust 层直接拒绝 |
| 结果展示 | ok / failed / skipped 三态；整体只有「全部成功 / 部分成功 / 全部失败」；失败项可单独重试 |

两处组合边界按「不改变数据安全规则」的方式处理：

- **快照与备份同选**：本次安全快照不参与清理；另一次独立的「清空本地备份」仍会删掉旧快照（那是用户的显式指令）。
- **隔离区归属**：隔离区路径在**执行开始时**锁定到当时的活动代际，避免切代际后静默漏掉用户要清理的那份。

**自动化**：`tests/data_reset.rs` 13 例（选项与组合、空库校验、指针不切、编号不丢、白名单、日志不越界、隔离区边界、失败跳过与重试）。**原生未验收**。
