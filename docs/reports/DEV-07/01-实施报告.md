# 01 · 实施报告

## 一、模块架构

```
src-tauri/src/backup/
├── mod.rs        模块入口与职责说明
├── zip_read.rs   读取 + 安全校验（DEV-01 已落地，本次复用，未另写一套规则）
├── manifest.rs   Manifest 生成、数据摘要、文件 SHA-256
├── create.rs     导出：快照 → 附件 → Manifest → ZIP → 自检 → 原子落位
├── restore.rs    恢复：预览 → 恢复前快照 → 隔离解包 → 校验/迁移 → 合并高水位 → 原子切换
└── state.rs      最近成功备份时间与提醒周期（本机状态，不进业务库）
```

## 二、创建备份的完整流程

1. 目标路径校验：必须绝对路径、`.zip` 结尾、不落在 `generations/` 或 `state/` 内、已存在则拒绝覆盖。
2. 在目标同目录建 `.artflow-backup-<uuid>.tmp/` 工作区（保证最终 rename 不跨卷）。
3. **一致性快照**：对活动代际的库执行 `VACUUM INTO work/database.sqlite`。
   WAL 模式下 `database.sqlite` 主体可能只有几 KB（内容都在 `-wal`），直接拷贝会丢数据；
   `VACUUM INTO` 由 SQLite 自己产出内部一致、含已提交事务的紧凑副本。
4. 对快照再跑一次 `PRAGMA integrity_check`，不是 `ok` 就中止。
5. 读快照统计订单/客户/模板/事件/附件/跳级/改期数量，读工作时区。
6. 取编号高水位 `HighWater::snapshot()`（独立于业务库的 `state/highwater.sqlite`）。
7. 收集附件：遍历 `attachments/originals`、`attachments/thumbs`、`attachments/quarantine`，
   拒绝符号链接，路径必须满足 `zip_read::reject_reason` 的 ASCII 相对路径规则。
8. 写 ZIP：`database.sqlite` → 各附件 → **最后**写 `manifest.json`；边写边算 SHA-256。
9. **自检**：`zip_read::inspect()` 全量回读（中央目录一致性、重复路径、路径安全、大小、SHA-256）。
10. 自检通过才 `fs::rename` 到目标路径，写 `state/backup.json`；任一步失败删除临时区并删掉目标文件。

## 三、ZIP 结构

```
database.sqlite                        # VACUUM INTO 快照
attachments/originals/<file>           # 原图，必须存在
attachments/thumbs/<file>.webp         # 缩略图（可重建，但照样备份）
attachments/quarantine/<file>          # 隔离区里仍有恢复价值的文件
manifest.json                          # 最后写入
```

## 四、Manifest 结构（格式 v1）

```json
{
  "format": "artflow-minidesk-backup",
  "formatVersion": 1,
  "appVersion": "0.1.0",
  "schemaVersion": 7,
  "createdAt": "2026-11-19T17:09:45.789Z",
  "workingTimezone": "Asia/Shanghai",
  "numberHighWater": [{ "year": 2026, "lastAllocated": 14 }],
  "files": [{ "path": "database.sqlite", "bytes": 249856, "sha256": "6118bd…" }],
  "totalFiles": 16,
  "totalBytes": 3264256
}
```

Manifest 不含本机绝对路径、不含用户名；`files` 只列数据文件，不自我引用（避免自校验循环）。

## 五、SHA-256 校验机制

- 写入时边写边算每个文件的摘要，写进 `files[].sha256`；
- 恢复前 `inspect()` 重新读取并逐文件比对 **大小 + SHA-256**，同时校验 `manifest.files` 与实际条目集合完全一致（去重、排序后比较）；
- Manifest 自身的完整性不靠自校验，而是靠「与实际条目集合一致 + 每个文件内容可验证」这一组合来约束；`manifest.json` 本身被篡改会直接导致集合或摘要不匹配。

## 六、恢复执行流程

1. `zip_read::inspect()` 全量校验；`format` 必须匹配，`formatVersion` 不得高于本程序支持值。
2. `schema_version > APP_SCHEMA_VERSION` → **拒绝**（提示先升级应用）。
3. **恢复前安全快照**：调用同一套 `create::create()` 导出当前数据到 `backups/pre-restore-<时间戳>.zip`。失败即取消恢复。
4. 生成新代际 id（`gen-<uuid>`），建 `attachments/originals`、`attachments/thumbs`。
5. 解包到新代际：逐条再跑一次路径规则、`target.starts_with(dest)` 越界检查、字节数与条目声明一致。
6. 数据库体检：`PRAGMA integrity_check` = ok、`PRAGMA foreign_key_check` 无违规、缺少 `database.sqlite` 直接拒绝。
7. 结构版本不等于 v7 时走既有迁移链 `migrations::migrate_to`（不手改版本号、不删旧字段），迁移后再校验版本与 `validate()`。
8. 附件引用核对：`attachments.state='ok'` 的行，`rel_path` 必须存在（缺 → 拒绝恢复）；`thumb_rel_path` 缺失只计数，允许后续重建。
9. 清理任务／作业改写：`cleanup_tasks` 里 pending 且指向 `attachments/%` 的行把 generation 改写为新代际（否则永远无法执行）；`attachment_jobs` 里属于旧代际的 pending 行置 `failed` 并写明原因。
10. 工作时区按 Manifest 恢复（非法 IANA 直接失败）。
11. 合并编号高水位：`max(本机, 备份)`，逐年比较，只升不降。
12. 写 `recovery/state.json`（phase=restore，记录前后代际）→ 原子写 `active.json` → 清除 state。
13. 返回新代际、旧代际、迁移来源版本、被抬高的年份、缺缩略图数、改写条数、恢复前快照路径。

## 七、generation 隔离与原子切换

- 恢复永远**不碰**当前活动代际：先建新目录、在里面解包/迁移/校验。
- `active.json` 通过 `write_json_atomic`（写 `.json.tmp` → `fsync` → `rename`）切换；
  中途崩溃时指针要么指旧、要么指新，不会出现半个 JSON。
- 切换前先落 `recovery/state.json`，重启时环境逻辑可据此判断「上次恢复/升级未完成」。
- 恢复成功后**不删除**旧代际，保留回退能力。

## 八、失败机制

| 失败点 | 行为 |
| --- | --- |
| 预览/校验失败 | 不创建任何目录 |
| 恢复前快照失败 | 取消恢复，当前数据不动 |
| 解包/体检/迁移/引用核对失败 | 新代际目录整体 rename 到 `recovery/failed-restore-<时间戳>-<id8>`，`generations/` 不留半成品；`active.json` 未动 |
| 高水位合并失败 | 新代际同样隔离，指针未切换 |
| 切换后崩溃 | `recovery/state.json` 记录 phase=restore，指针已指向新代际且新代际已验证 |

诊断目录**不自动清理**，失败现场留着便于排查。

## 九、前端交互

设置页新增「数据备份」模块（Arctic Blue 既有样式，无新视觉语言）：

- 上次成功备份时间 + 「今天已备份 / N 天前 / 从未备份」
- 结构版本 / 备份格式版本、当前数据代际、订单/附件数/库体积
- 到期横幅：「已有 N 天没有备份，建议现在导出一份。」
- 「导出备份…」→ 系统保存面板 → 成功后显示文件数、体积、路径
- 「从备份恢复…」→ 系统打开面板 → 预览摘要（来源时间、版本、订单/客户/模板/事件/附件、跳级/改期条数）→ 兼容性说明 → 确认框（危险操作样式）
- 恢复完成 → 显示新代际结果 + 恢复前快照路径 + 「立即重启」（`restart_app`）
- 提醒周期下拉：关闭 / 7 / 14 / 30 / 90 天（默认关闭，不由程序替用户决定）
- 状态读取失败只在本模块内提示，不占用页面级错误区
