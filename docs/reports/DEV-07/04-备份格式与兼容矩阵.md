# 04 · 备份格式与兼容矩阵

## 一、版本

| 版本 | 当前值 | 定义位置 | 变化规则 |
| --- | --- | --- | --- |
| 备份格式版本 | **v1** | `src-tauri/src/backup/zip_read.rs::FORMAT_VERSION` | 只有「旧程序读不懂新增必要结构」时才升 |
| 数据库 Schema 版本 | **v7** | `src-tauri/src/store/migrations/mod.rs::APP_SCHEMA_VERSION` | 每次结构迁移 +1 |
| 应用版本 | `CARGO_PKG_VERSION` | `Cargo.toml` | 随发布递增 |

三者独立：格式 v1 可以承载 schema v7，将来也可以是 schema v9 的包。

## 二、Manifest 字段（v1）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `format` | string | 固定 `artflow-minidesk-backup`，不匹配即拒绝 |
| `formatVersion` | u32 | 高于程序支持值即拒绝 |
| `appVersion` | string | 导出方应用版本（只作参考，不参与兼容判断） |
| `schemaVersion` | i64 | 数据快照的结构版本，恢复时决定「直接可用 / 迁移 / 拒绝」 |
| `createdAt` | RFC3339 | 导出时间（UTC） |
| `workingTimezone` | IANA string | 恢复后写回工作时区；非法值导致恢复失败 |
| `numberHighWater` | `[{year,lastAllocated}]` | 逐年编号高水位 |
| `files` | `[{path,bytes,sha256}]` | 每个数据文件的大小与摘要 |
| `totalFiles` / `totalBytes` | int | 汇总，便于快速拒绝异常包 |

未定义的额外字段在读取时被忽略（前向兼容）；但**必要能力**（新格式版本）不做静默降级。

## 三、ZIP 内部结构

```
database.sqlite
attachments/originals/<name>
attachments/thumbs/<name>
attachments/quarantine/<name>
manifest.json
```

规则：只用 `/` 分隔的相对路径、不允许绝对路径、不允许 `..`、不允许盘符／空段／控制字符、不允许重复条目、不允许符号链接。附件目录不写死本机路径与用户名。

## 四、校验机制

1. ZIP 可解析、中央目录完整；
2. 条目路径全部通过安全规则；
3. `manifest.files` 与实际条目集合**完全一致**（排序去重后比较）；
4. 每个条目 `bytes` 与 `sha256` 与 Manifest 一致；
5. `database.sqlite` 可打开且 `PRAGMA integrity_check = ok`；
6. `PRAGMA foreign_key_check` 无违规；
7. `formatVersion`、`schemaVersion` 在支持范围内。

## 五、兼容矩阵

| 备份 schema | 当前程序（v7）行为 | 结果 |
| --- | --- | --- |
| v1–v6 | 在**新代际**内沿迁移链升级到 v7 | 允许（需迁移测试通过） |
| v7 | 直接使用 | 允许 |
| > v7 | 拒绝，提示先升级应用 | 拒绝（`schemaRelation: newer`） |
| `formatVersion` > 1 | 拒绝 | 拒绝 |
| `formatVersion` = 1 | 允许 | 允许 |
| 其它 `format` 值 | 拒绝 | 拒绝 |

| 包内容异常 | 行为 |
| --- | --- |
| ZIP 损坏 | 拒绝（校验阶段，不建目录） |
| 缺 `manifest.json` | 拒绝 |
| Manifest JSON 非法 | 拒绝 |
| 缺 `database.sqlite` | 拒绝 |
| SHA-256 / 大小不符 | 拒绝 |
| 数据库无法打开 / integrity 失败 | 拒绝 |
| 缺原图（`state='ok'` 引用） | 拒绝整套恢复 |
| 缺缩略图 | 允许，计入 `missingThumbs`，可重建 |
| 路径越界 / 绝对路径 / 重复条目 | 拒绝 |
| 高水位低于本机 | 取本机（不降） |

## 六、未来格式升级原则

1. **只加不改**：新增可选字段不升 `formatVersion`，旧程序忽略即可；
2. 新增**必需**结构（旧程序必须理解才能正确恢复）才升 `formatVersion`，并在读取侧显式拒绝低版本无法处理的包；
3. 数据库新增表／字段不需要改备份代码——备份是整库 `VACUUM INTO` 快照，不列举业务表；
4. 附件目录若新增子目录，只需加入收集清单（`ATTACHMENT_DIRS`），不需改格式版本；
5. 跨平台：路径统一 `/`、不写绝对路径、不写用户名、不依赖固定数据目录名；Windows 侧运行时验收留待 DEV-09。

## 七、当前不承诺的能力

- 备份包加密（产品未决定，未实现；界面已提示包含敏感业务数据）；
- 自动定时备份与增量备份；
- 单文件级恢复（当前是整包恢复）；
- 反向兼容（用 v1 程序读未来格式）。
