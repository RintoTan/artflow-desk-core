# 布局和交互修复（Batch A）

## UX-10 订单操作栏

- 宽详情（操作栏 ≥620px）：`制作进度` 组（开始制作 / 撤销开工 / 推进阶段…）+ `订单状态` 组（完成 / 取消订单… / 重新打开）同一行，间以竖线；去掉了把第二组推到右端的 `margin-left:auto`。
- 窄详情（<620px）：保留主要动作与「完成」（可用时），其余进入原生 `<details>` 的「更多操作」菜单；菜单内保持取消订单的危险描边与原有确认流程。
- 宽度判定用 `ResizeObserver` 观察操作栏自身，不是窗口宽度；jsdom 无 `ResizeObserver` 时保持宽布局，不报错。
- 未改：状态判断、未开工/终态限制、统一阶段入口、取消确认、revision、事件、禁用原因（仍在 `title` 与菜单项可用性上）。

实测：900px 窗口下操作栏宽 545px → 收为一行三个控件（截图 `screenshots/07-订单-900-操作栏.png`）。

## UX-11 订单列表滚动条

- 删除 `[data-theme="dark"] ::-webkit-scrollbar` 整段（10px 轨道 + `#33455a` thumb）。浅色原本没有自定义，深色现在与浅色一致，交还 macOS 原生覆盖式滚动条，并尊重系统"总是显示"偏好。
- 未使用 `scrollbar-width: none`，没有隐藏内容，也没有压缩列表操作区。

## SET-FIX-01 设置页保存栏

- `.settings-savebar` 改为普通文档流（`position: static`）、实色 `var(--surface)`、去掉 `backdrop-filter`；删除矮窗口那条 sticky 例外。
- 结构不变：未保存状态 + 保存设置 + 放弃修改 + 恢复默认主题；宽度不足时按钮换行（既有 `flex-wrap`）。
- 恢复默认主题仍需确认；确认后只重置草稿。
