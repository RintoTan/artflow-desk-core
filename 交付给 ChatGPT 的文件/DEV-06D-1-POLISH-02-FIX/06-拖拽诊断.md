# U2 Finder 拖拽诊断

## 调用链

Finder → Tauri（dragDrop 默认开启）→ `getCurrentWebview().onDragDropEvent`
→ `{type, paths, position}` → `AttachmentPanel` → `partitionImagePaths`（扩展名预过滤）
→ `attachmentApi.import({orderId, sourcePaths})` → `invoke("attachment_import")`
→ Rust `commands::attachments::attachment_import` → `attachments::import`
（魔数解码、100MB 上限、落盘、写 attachments / attachment_jobs）。

## 旧实现的两个可验证缺陷

1. `drop` 用"落点在矩形内"作为**是否导入**的闸门；`position` 若与 `getBoundingClientRect`
   不是同一坐标系（物理像素 vs 逻辑像素），命中恒为 false，拖到面板上也静默无反应。
2. 命中失败不报错、不去重，用户看不到任何提示。

## 本轮修改

- `drop` 直接导入 `payload.paths`（面板只在选中订单时订阅，drop 即"给当前订单"）；
  坐标只用于 `over` 高亮。
- 高亮命中同时按 `1` 与 `devicePixelRatio` 试算，并对齐到 `.orders-detail` 外扩 8px。
- 800ms 内重复 `drop` 只处理一次。
- `paths` 为空时明确提示，不再静默。

## 仍未验证

真实 Finder 拖放 = **NOT RUN**；Mac 上 `payload.position` 的实际刻度未取证。
"物理/逻辑像素"是根据代码与 Tauri 2 文档的推断，不是抓到的现场数据。

## 实机复验步骤

1. QA identifier + `seeded` 场景，打开任一订单。
2. 拖 1 张 PNG 到空状态：面板描边高亮，松手后提示"已导入 1 张图片"。
3. 再拖 1 张 JPG 到已有图片区：追加成功。
4. 拖 `.gif` / `.pdf`：提示不支持，且无新增附件。
5. 拖 >100MB PNG：显示后端拒绝原因。
6. 拖拽中途移出窗口：高亮熄灭，不重复导入。
7. 结束后核对 `attachment_list` 数量与文件名。
