# ArtFlow Desk Core — DEV-06D-1-UX-04｜缺陷诊断与修复

## P1-02 看板阶段导航无法返回（已定位根因并修复）

**根因（代码级、可复现）**：`OrderBoard.goToColumn()` 里

```ts
const target = board.querySelector(`[data-col="${key}"]`);
if (!target) return;      // ← 先返回
setCurrentKey(key);       // ← 永远轮不到
```

聚焦到靠后阶段时，`visibleColumns` 只剩当前切片，`草稿 / 线稿` **根本没渲染**，
`querySelector` 返回 null，函数直接 return —— 状态没变，切片不变，于是"往前点"永远无效。
这也解释了为什么"顺序从第一个点到最后一个"看起来正常：那时目标总在切片里。

**修复**：`goToColumn` 只负责 `setCurrentKey(key)`；滚动交给 `useEffect`，
等切片重算、DOM 更新后再找目标列滚动。滚动前判 `typeof board.scrollTo === "function"`
（jsdom 没有）。

**回归测试**：`OrderBoard.test.tsx` 新增「阶段导航可以双向切换」——
用 5 个阶段构造必然切片（阶段数 5 > 一次可见 3），先跳最后再点第一个。

## P1-01 拖拽在 WKWebView 失效（已移除误导性 UI）

QA-02 实机 FAIL，且此前的拖拽柄在实机上"只出现点状抓手、无确认框"。
本轮**不再主张 HTML5 DnD 可用**，按任务要求移除：

- 删除 `.board-card-grip`、`draggable`、`dragstart/dragend`、列上的
  `dragenter/dragover/dragleave/drop`，以及 `handleDrop` 函数。
- 对应测试改为断言「DOM 中不存在 `.board-card-grip` 与 `[draggable=true]`」。

**未归因到平台**：代码里确实存在两处可疑写法（整卡是 `<button>`；自定义 MIME），
但**没有在 WKWebView 复现并定位到具体环节**，因此只作为待验证假设记录，不写成根因。

## 新的稳定路径：显式阶段操作

每张活动订单卡片新增「阶段操作」按钮（`aria-haspopup="menu"`），展开该订单
**自身模板**的全部其它阶段：

- 合法单步动作（推进/返工）→ 可点，点击后弹**同一个** `ConfirmDialog`；
- 不可达 → 禁用，并用 `title` 说明原因（"无法通过单个合法动作到达该阶段"
  或领域层给出的具体理由）。

底层仍然是 `planStageMove` + `advance_stage` / `rework_stage`，
未新增命令、未直接写 `current_stage_id`，revision 冲突与取消零写入照旧。

**测试**：「阶段菜单里的每一项要么是合法单步动作，要么禁用并说明原因」——
逐项点禁用项断言不弹框，点第一个可点项断言弹框且**未**调用 `onApply`（确认前零写入）。
