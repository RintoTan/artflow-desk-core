# 头部 UI 三方案比较（原型，非正式实现）

原型：`docs/prototypes/ui04-variants.html`（纯 HTML/CSS，Blink 截图）

| | A 经典桌面工具栏 | B 搜索驱动 | C 上下文工具条 |
|---|---|---|---|
| 一级 | 标题/数量 + 视图段控件 + 新建 | 标题 + 视图 + 新建 | 标题 + 视图 + 新建 |
| 二级 | 搜索 + 来源 + 状态 + 导出（左对齐一行） | 搜索独占整行；筛选折叠为「筛选 (2)」+ 生效条件小标签 | 随视图变化：卡片=密度、看板=总览/聚焦、表格=列设置 |
| 900px | 一行放得下，最紧凑 | 搜索最舒服，但多一行 | 最省空间，控件位置会随视图变 |
| 1400px | 两侧留白偏多 | 搜索过长需限宽 | 布局稳定 |
| 生效筛选可见性 | 强（胶囊常显） | 中（需展开，但有条件标签） | 强 |
| 学习成本 | 低 | 中 | 中（控件会变） |
| 主要风险 | 与 UI-03 差别最小，用户已否定"分层" | 多一行高度；筛选入口需点开 | "位置随视图变"可能与"切换按钮位置固定"冲突 |

**推荐**：A 作为基线 + 吸收 B 的"生效条件标签/一键清除"，不采用 C 的随视图换控件
（与已验收的"页头位置稳定"约束冲突）。

**待用户裁定**：最终选 A / B / C。
