# ArtFlow Desk Core — DEV-06D-1-UX-05｜QA-03 缺陷诊断

## U2 阶段操作弹窗（FAIL）

**定位到的是我自己引入的一层**：上一轮把「阶段操作」做成了 `position: absolute` 的浮层菜单
（`.stage-menu`），它挂在 `.board-card-actions` 里，而祖先链上有
`.board-cards`（`overflow` 滚动/裁切）与 `.board-col`。绝对定位元素被滚动容器裁切，
于是出现"布局混乱、点不动"。

`ConfirmDialog` 本身一直是 `createPortal` 到 body，**不是它的问题**；出问题的是那个浮层。

**修复**：删除浮层菜单，改为**一个**选择对话框（复用同一个 `ConfirmDialog`）：
单选列表 → 选目标 → 确认 → 进入已有的变更确认对话框。
全程 portal 渲染，不受卡片宽度与滚动容器影响；`⋯` 按钮只占 26px。

**状态**：代码修复完成，前端测试通过；**WKWebView 实机未验证**（不宣布实机通过）。

## U6 聚焦模式横向溢出（PARTIAL）

在 Blink 下无法复现：880 / 900 / 1100 / 1400 四个宽度，`.board` 的
`scrollWidth == clientWidth`，且探针遍历 `.board` 所有后代，**没有任何元素** `scrollWidth > clientWidth`。

因此本轮做的是**加固而非"修根因"**：flex/grid 子项默认 `min-width: auto`，
CJK 字体度量下会把卡片顶宽。已显式给
`.board-col / .board-cards / .board-card / .board-card-open / .board-card-meta / .board-card-foot`
设 `min-width: 0`，客户名 `overflow-wrap: anywhere`。
**未使用 `overflow: hidden` 遮挡**。

**仍待 Mac 复验。**

## U6 底部贴边（PARTIAL）

此前的断言只读 `padding-bottom`（我的实现里给了 22px），但**滚到底时的真实距离**从未被测。
本轮改为测量：滚动到底 → 最后一项 `getBoundingClientRect().bottom` 与视口下边界之差。
看板实测 **52px**；表格的滚动容器其实是 `.table-wrap`（`overflow-x:auto`），
原来的 `::after` 加在了不存在的 `.table-scroll` 上，等于没生效——已改到 `tbody::after`。
断言阈值改为"实测 ≥16px"。
