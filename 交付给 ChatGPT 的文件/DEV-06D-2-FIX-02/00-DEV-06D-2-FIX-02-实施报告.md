## 3. ISSUE-01 订单标题显示不完整

### 3.1 根因

`.timeline-info` 是 56px 高的列向 flex 容器，`padding: 8px 12px` 后内容盒只有 40px，而三个子元素的自然高度合计约 48.2px：

```text
编号 10.5px → 约 14.2px（line-height: normal）
标题 12.5px → 约 17.0px
客户/阶段 11px → 约 15.0px
gap 1px × 2
────────────────────────
合计 ≈ 48.2px  >  内容盒 40px
```

子元素默认 `flex-shrink: 1`，于是三者按比例被压缩：标题从 17px 被压到 **11.33px**，而 `.timeline-title` 是 `overflow: hidden`，字形下半截直接被切掉。AUTO-QA-01 用父元素 `scrollHeight > clientHeight` 判断，父元素本身高度被 `height` 钉死、子元素又被压缩到刚好塞下，所以那个判据永远为 false —— 这也是旧测量方法漏判的原因。

### 3.2 修复

```css
.timeline-info { padding: 6px 12px; }            /* 内容盒 44px */

.timeline-code  { line-height: 12px; flex: none; }
.timeline-title { line-height: 17px; flex: none; min-width: 0; }
.timeline-sub   { line-height: 12px; flex: none; min-width: 0; }
```

- 三行固定行高合计 41px + gap 2 = 43px ≤ 44px，装得下。
- `flex: none` 禁止再被压缩，`overflow: hidden` 只在横向起作用（单行省略号）。
- 行高仍是 56px（窄容器 52px），行高变量、左右列坐标一律未动。

### 3.3 修复前后测量（真实浏览器）

| 视口 / 容器 | 行高 | 信息列 | 标题 clientHeight | 标题 scrollHeight | line-height |
|---|---:|---:|---:|---:|---|
| 修复前（AUTO-QA-01，容器 900） | 56 | 235 | **11.33** | **17** | normal |
| 修复后 · 视口 900 | 52 | 177 | 17 | 17 | 17px |
| 修复后 · 视口 1400 | 56 | 299 | 17 | 17 | 17px |
| 修复后 · 视口 1680 | 56 | 299 | 17 | 17 | 17px |
| 修复后 · 容器 900 | 56 | 235 | 17 | 17 | 17px |

长标题（86 字，无空格）：`clientWidth 211 / scrollWidth 791`（容器 900）、`275 / 791`（1400、1680），`text-overflow: ellipsis`、`white-space: nowrap` —— 只发生横向省略，不产生纵向裁切。短标题 `clientWidth == scrollWidth`，不触发省略号。

DOM 里的标题始终是完整原文（不含 `…` 字符），完整名称可通过 `title` 属性与链接自身的可访问名称取得，键盘用户 Tab 到链接即可朗读全文。见联系表第 2、3 张。

## 4. ISSUE-02 周视图日期范围异常

### 4.1 用户原始反馈

> 周窗口 2026-10-26 ~ 2027-01-17；观察到的范围 10-16 ～ 01-17；实际显示 10-16 ～ 01-11。

### 4.2 四个概念分别实测（今天 = 2026-11-18，Asia/Shanghai）

| 概念 | 实测值 | 说明 |
|---|---|---|
| A 窗口起止 | 2026-10-26 ~ 2027-01-17 | 84 天，10-26 周一、01-17 周日 |
| B 可视起止（scrollLeft = 0） | 2026-10-26 ~ 2026-11-23 | 618px ÷ 26px/天 ≈ 23 天 |
| B 可视起止（滚到最右） | 2026-12-20 ~ **2027-01-17** | 终点正好是窗口终点 |
| C 末周刻度 | **2027-01-11**（周一） | 12 个刻度：10-26 / 11-02 / 11-09 / 11-16 / 11-23 / 11-30 / 12-07 / 12-14 / 12-21 / 12-28 / 01-04 / 01-11 |
| D 画布 | 2184px = 84 × 26 | 末刻度左缘 + 7 天 = 画布右缘（半开区间到 01-18，视觉止于 01-17） |

网格线 12 条，全部落在周一；因为网格线画在刻度**左缘**，所以最后一条线在 01-11，画布仍继续 6 天到 01-17，这一段没有竖线、也没有新标签。

### 4.3 结论：算术与渲染符合规格（NOT A BUG）

- 窗口 = 今天前 21 天所在周的周一 → 后 56 天所在周的周日，共 12 个完整自然周 = 84 天。✔
- 「01-11 是最后一个刻度」正是规格要求：周刻度只标周一，01-11 是窗口内最后一个周一，01-17 是它所在周的周日。把 01-11 当成窗口终点是读法问题，不是计算问题。
- 「10-16」在周尺度下不可能出现：它比窗口起点 10-26 早 10 天，而周尺度坐标是 `(day − 窗口起点) × 26px`，`scrollLeft` 不能为负；再往上，任何周窗口的起点都必然是周一，而 **2026-10-16 是周五**，因此它不可能是本产品任何一周的窗口起点，也不可能是周尺度的可视起点。

### 4.4 本轮改动（仅文案，不改计算）

周尺度说明行追加一句：`周一刻度，末周起 2027-01-11`。这样「最后一条竖线/最后一个标签是 01-11」和「窗口到 01-17」在同一行里说清楚，避免再把末刻度当终点。

`timeline.ts` 的窗口、刻度、画布、`WEEK_START_OFFSET` **一行未改**。

### 4.5 仍 OPEN 的部分

「10-16」这一半无法复现，也无法由当前代码产生（见 4.3 的反证）。因此 **ISSUE-02 保留 OPEN**，需要你确认当时看的是哪一处文字（是「可见 …」还是轴上的月份标签），或提供截图；否则不能宣布关闭。01-11 的一半已有充分证据，判定为符合规格。

## 5. UX-TL-01 订单日期悬浮提示

### 5.1 实现

- 新增纯函数 `dateTipLines(order)`：只读 `plannedStartDate` / `plannedDeliveryDate` 原始值，不使用裁切后的可见区间；`YYYY-MM-DD` 用现成的 `parseDayKey` 校验后格式化，不新增日期解析。
- 区间条与单端标记获得 `tabIndex=0`、`role="img"`、`aria-label="<编号> 排期：…"`；`onPointerEnter/Leave`、`onFocus/Blur` 控制提示。
- 提示用 `position: fixed` + `createPortal` 挂到 `document.body`：横向滚动容器裁不到它，`pointer-events: none` 不阻断点击，fixed 元素不参与页面滚动尺寸计算，因此不会产生横向溢出。滚动时主动收起，避免坐标残留。
- 提示固定在图形上方 10px，`max-width: 240px`，左右按视口夹紧。

### 5.2 各形状实测

| 订单形状 | 提示内容 | 渠道 |
|---|---|---|
| 开始 + 交付 | 开始日期：2026-11-04 / 交付日期：2026-11-12 | 鼠标悬浮 ✔ 键盘聚焦 ✔ |
| 只有开始 | 仅开始 / 开始日期：2026-11-09 | 鼠标 ✔（联系表第 4 张） |
| 只有交付 | 仅交付 / 交付日期：2026-11-16 | 组件测试 ✔ |
| 同一天 | 2026-11-15 / 单日排期（日期只出现一次） | 组件测试 + 浏览器 ✔ |
| 部分越出窗口 | 仍是完整 2026-08-01 ~ 2026-09-10 | 组件测试 ✔ |
| 已结束 | 与活动订单同一规则 | 组件测试 ✔ |
| 完全未排期 | 轨道上没有图形，因此没有提示，也不编造日期 | 组件测试 ✔ |

### 5.3 交互与副作用实测

| 检查 | 结果 |
|---|---|
| 鼠标离开后消失 | `tip 存在=false` |
| 失焦后消失 | `tip 存在=false` |
| 提示不改变行高 | `rowH 56 → 56` |
| 提示不造成页面横向溢出 | `scrollWidth 1400 → 1400` |
| 提示不吃鼠标事件 | `pointer-events: none` |
| 提示仍在视口内 | `left 790 / right 934 / top 629`（视口 1400×1300） |
| 排期图形本身仍在命中链上 | `elementFromPoint = .timeline-bar` |
| 在条上点击仍跳转 | 组件测试：点击 <悬浮已显示提示> 的条 → `/orders?orderId=click-target` ✔ |

> 浏览器脚本**没有**做真实点击跳转断言：该脚本的夹具只覆盖工作台需要的命令，直接进 `/orders` 会因缺少订单页数据回退到工作台，属夹具限制。这条由 jsdom + MemoryRouter 覆盖，不把它写成浏览器 PASS。
