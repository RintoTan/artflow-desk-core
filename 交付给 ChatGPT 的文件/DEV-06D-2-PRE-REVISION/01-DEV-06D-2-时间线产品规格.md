## 1. 定位与边界

时间线是**工作台内的一个模块**，不是独立页面。

工作台顺序（自上而下）：

1. 页头：标题「工作台」+ 今天/工作时区 + 关注计数徽标。
2. 经营指标：现有 8 张指标卡（不改口径）。
3. **跨订单项目时间线**（本规格）。
4. 提醒说明（现有面板，原样保留）。

明确不做：

- 左侧导航不新增「项目时间线」入口。
- 不复制独立的时间线管理页。
- 不替代 DEV-06D-3 日历：时间线回答"这段时间里各单怎么排"，日历回答"某一天要做什么"。
- 不做拖拽改期、不算完成进度、不自动补日期、不新增排期数据表。

### 2.1 两列为什么不做"一个滚动容器 + sticky"

- 左侧信息列固定、右侧轨道独立横向滚动：`grid-template-columns: var(--info-w) minmax(0,1fr)`，左右两列各自纵向排列，行高统一为 `--row-h`（56px，窄容器 52px）。
- 表头（双层刻度）与轨道行**在同一个横向滚动容器里**，因此天然共用同一套 x 坐标，不需要 JS 同步 scrollLeft。
- 代价：表头不是 `position: sticky`（页面滚动时表头会滚出）。这是一次**有意的取舍**：工作台整体纵向滚动，若把表头做成 sticky，就必须给时间线自己套一个纵向滚动容器（任务书禁止"大型嵌套纵向滚动区"）。
  补偿：状态行始终写明"可见 … ~ …"，即使表头滚出，当前范围仍然可读。
- 已用几何断言锁定：信息列第 i 行与轨道第 i 行的 `getBoundingClientRect().top` 差 ≤ 0.5px；`.tl-corner` 底边与 `.tl-axis` 底边同 y。

## 3. 四种尺度

| 尺度 | 窗口（以今天 2026-11-18 为例） | px/天 | 画布宽 | 第一层刻度 | 第二层刻度 | 前后翻页步长 |
|---|---|---|---|---|---|---|
| 日 | 今天 −7 … +13（21 天） | 44 | 924 | 月 | 逐日（日 + 周一~周日单字） | 7 天 |
| 周 | 今天 −21 …+56，再对齐到整周（周一 → 周日） | 26 | 2184 | 月 | 每周一（`MM-DD`） | 28 天 |
| 月（默认） | 当月 −2 月 … +10 月，按自然月首尾对齐 | 6 | 2370 | 年 | 每月 1 日 | 1 个自然月 |
| 年 | 当年 −1 年 … +4 年，按自然年对齐 | 1.8 | 3287 | 年 | 季度 Q1–Q4 | 12 个月 |

- 窗口只跟"今天"和尺度有关，**不随筛选变化**：所有行共享同一坐标系。
- 月/年尺度按自然月/自然年对齐，避免出现半截月、半截年的列。
- 周起始：项目内**没有**既有周起始规范（全文检索无 week 相关逻辑）。本规格采用 ISO 8601（周一），**标为待裁定项**，一旦产品选择周日起算，只改 `weekdayMon` 的偏移。
- 位移时保持锚点日期；月位移用"夹到月末"（1-31 + 1 月 → 2-28），不会溢出到 3 月。

### 3.1 为什么"日视图"没有小时刻度

订单只有 `planned_start_date` / `planned_delivery_date` 两个**日历日期**字段，没有任何时刻。在日视图里画小时刻度会制造不存在的时间精度，因此日视图的下层刻度是"日"，不是"小时"。这是产品决策，不是遗漏。

## 4. 日期规则（逐情形）

| 数据情形 | 时间线表现 | 依据 |
|---|---|---|
| 开始 + 交付 | 画区间条：`left = dayToX(start)`，`width = (due − start + 1) × pxPerDay`（含首尾两天） | 复用 `scheduleBar.barModel` 的语义 |
| 仅有开始 | 只画一个空心圆标记 + 「仅开始」文字，不画条 | 不虚构交付日 |
| 仅有交付 | 只画一个菱形标记 + 「仅交付」文字，不画条 | 不虚构开始日 |
| 两者皆无 | 不进时间线，进「未排期」区 | 不自动补日期 |
| 同日开始与交付 | 单日条，宽度取 `max(pxPerDay, minBar)` | 位置仍由真实日期决定 |
| 开始晚于交付 | 不画条，只画两个标记 + 「日期顺序异常」 | 数据库 `CHECK (planned_delivery_date >= planned_start_date)` 已阻止该数据；这里只是防御性渲染 |
| 整段早于窗口 | 不画条、不贴边；行内显示两个越界标记 + 左向箭头 | 不把越界日期伪装成边界日期 |
| 整段晚于窗口 | 同上，右向箭头 | 同上 |
| 部分越界 | 条被裁到窗口内，裁切边加 `◀` / `▶` 提示，`title` 写明真实日期 | 保留方向信息 |
| 跨月 | 连续条，跨过月分隔线 | 坐标是"天序号 − 窗口起点"，与月份无关 |
| 跨年 | 连续条，第一层刻度按年分组 | 同上 |
| 闰年 2 月 29 日 | 合法，正常定位 | `civilFromDays` 回读校验 |
| 非法日期（`2026-02-30`、`2026-1-1`、`2026-13-01`） | 视为"没有该日期" | `parseDayKey` 返回 null |

### 4.1 日期与工作时区

- 计划日期是**日历日**，不做任何时区换算；只有 `started_at / completed_at / cancelled_at` 这类瞬时才用工作时区换算（`localDayIndex`）。
- 「今天」= `localDayIndex(now, workingTimezone)`，时区来自既有设置（`status().workingTimezone`），不硬编码。
- 逾期语义**只读**后端的 `deadlineState`，前端不重算。
- 与后端口径的一处差异必须记住：**后端的"未排期"= 没有交付日期**（`domain/dashboard.rs` 按 `planned_delivery_date IS NULL` 计数），而**时间线的"未排期区"= 起止都没有**。所以"只有开始日期"的订单：指标里算未排期，时间线上仍会画出来。原型已按此实现（`full` 场景：指标"未排期"=2，时间线未排期区 =1）。

## 5. 刻度与坐标系

- 唯一映射：`x = (day − window.from) × pxPerDay`。表头、条、标记、今天线全部用它。
- 第一层刻度宽度 = 该时间段跨越的整天数 × pxPerDay，边界与第二层严格对齐（自检：月刻度宽度总和 = 画布宽，容差 0.5px）。
- 刻度标签用 `position: sticky; left` 吸附在滚动视口左缘，但不会越过自己所属的时间段 —— 解决"滚到年中却看不到年份"的问题。
- 今天线：`x = dayToX(today) + pxPerDay/2`，1px 红色虚线，跨表头以下全部行；表头里有「今天」小旗。

## 6. 交互

| 交互 | 行为 |
|---|---|
| 日/周/月/年 | 真正重算窗口与刻度，不只是切换按钮状态 |
| ‹ / › | 按尺度步长平移窗口；平移后滚动位置回到起点，避免"翻页后看不到内容" |
| 今天 | 锚点回到今天，并把今天滚到视口 45% 处 |
| 横向滚动 | 只作用于右侧轨道；左侧信息列不动；页面本身不横向滚动 |
| 滚到末端 | 右侧渐隐提示消失 |
| 显示已结束 | 勾选后追加 `complete` / `cancelled` 行，用虚线中性条，不参与风险着色 |
| 点订单行 | 跳 `/orders?orderId=<id>`（沿用既有下钻参数）；键盘 Tab + Enter 同样可用 |
| 未排期条目 | 同样是链接，进详情补日期 |

**原型里的点击只弹提示条**（"原型反馈：将进入订单 … 的详情。原型不接真实路由"），不会真的跳转 —— 原型没有路由。

### 6.1 空状态与异常

| 情形 | 表现 |
|---|---|
| 没有任何订单 | 空面板「还没有任何订单」+ 说明；未排期区显示 0 |
| 有订单但都没有日期 | 空面板「没有任何订单填了计划日期」；未排期区列出全部 |
| 活动订单全被终态过滤 | 空面板「活动订单都已完成」+ 提示勾选"显示已结束" |
| 读取失败（实施阶段） | 独立错误面板 + 重试；不回退到示例数据 |

## 7. 响应式

按**时间线容器的实际宽度**（`@container workspace`），不是窗口外框。

| 窗口 | 主区容器 | 时间线框 | 信息列 | 轨道可视宽 | 指标列数 |
|---|---|---|---|---|---|
| 900px | 604px | 547px | 178px | **369px** | 3 |
| 1400px | 1104px | 1047px | 300px | **747px** | 4 |
| 1680px | 1384px | 1327px | 300px | **1027px** | 8 |

（以上为原型 `?geom=1` 实测值。）

- < 640px 容器：隐藏"客户/金额"副行，行高 52px，信息列 178px。
- 宽屏不放大 `pxPerDay`：年/月尺度的窗口是固定的，画布宽度因此固定，宽屏只是"一屏看到更多"，不会把日期拉稀。
- 矮窗（400px 高）：时间线不设内部纵向滚动，跟着页面滚。

## 9. 性能与刷新

- 刻度数量：日 21、周 ~11、月 13、年 ≤ 24 —— 不需要虚拟化刻度。
- 行渲染：`content-visibility: auto` + `contain-intrinsic-size: 56px`；200 行以内不虚拟化，超过再加窗口化（写在风险里）。
- 数据变化：进入工作台、窗口重新获得焦点、点"刷新"时重取；不做轮询。
- 切尺度只重算几何，不重新请求数据。

## 11. 与 DEV-06D-3 日历的共享边界

- 共享：`DayIndex`、`parseDayKey`、`localDayIndex`、「今天」、工作时区、按天定位的坐标思想。
- 不共享：时间线是**只读**，日历未来会写日期。日历的拖放**写哪个字段**（开始/交付/两者）属于 DEV-06D-3 的独立决策，本规格不预设。
- 日历可以有自己的月网格生成器，但不得引入第二套日期库或第二套"今天"算法。

## 12. 未决问题（需裁定）

1. **周起始**：ISO 周一（当前采用）还是周日起算？
2. **终态默认**：默认隐藏（当前）还是默认灰显？
