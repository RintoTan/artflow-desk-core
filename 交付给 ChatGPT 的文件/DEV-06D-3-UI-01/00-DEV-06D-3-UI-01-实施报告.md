## 3. 拖拽预览实现

**结构**（全部由现有状态派生，无新业务字段）：

```text
drag = { order, mode, targetDay, plan, blocked }
  ├─ plan 来自 dropPlan(order, targetDay, mode) —— 未改一行
  ├─ previewRange = { from, to, valid }  ← 由 plan 的两个日期解析（parseDayKey）得到
  └─ Grid 按周切片：colStart/colEnd = preview.from/to − 该周周一
```

- **原位置**：被拖的 chip 保持原轨道与位置，加 `.is-ghost`（opacity 0.32 + 虚线 + 轻微去饱和），不消失。
- **目标位置**：每个受影响的周渲染一条 `.cal-preview`，`left/width` 用列百分比（`col/7`），因此**长度严格等于修改后的真实区间**；跨周会分成多段并在几何上相接（1400 下两段 346+461=807=整周宽）。
- **日期反馈**：网格上方出现 `.cal-drag-status`，两行 `开始日期 旧 → 新`、`交付日期 旧 → 新`；只有真正变化的端点加粗高亮。
- **非法**：`dropPlan` 返回 `{ok:false}` 时预览变红（`data-valid="0"` + `.is-invalid`），状态区变红并给出 `plan.reason` 原文（如「计划交付日期不能早于计划开始日期」），松开不进确认框。
- **三段落点**：`pointerdown` 依据指针在条内的横向比例判定——左 25%（且该端在此周）→ 改开始、右 25% → 改交付、中间 → 整体平移；单日订单恒为整体移动。原先只有整体移动，本次补上两端（规格 §9.2 已要求，`dropPlan` 早已支持 `start`/`delivery`）。
- **跨周/跨月**：延续段（`clippedLeft/Right`）不提供端点操作，只能整体平移，避免把中间周误当端点。

**未变**：`dropPlan()`、`rescheduleInput()`、状态机顺序（拖动→预览→松开→确认→写入）、`ConfirmDialog`、revision 冲突处理。

## 4. 控件尺寸统一

| 控件 | 高度 | 依据 |
|---|---:|---|
| 上一段 / 下一段（图标） | 34（正方形） | 全站 `--control-h` |
| 今天 / 刷新 | 34 | 同上 |
| 月 / 周 分段 | 容器 34（内按钮 28 + padding 3） | 与订单页分段控件一致 |
| 显示已结束 | 34（含 checkbox 行高） | 与工具栏齐平 |

| +N 浮层按钮 | 28 | 同上 |
| 弹窗日期 / 原因输入 | 34 | 全站输入高度 |
| 弹窗确认 / 取消 | 沿用 `ConfirmDialog` 现有规格 | 未覆盖 |

统一了字号（11.5/12.5）、圆角（9/8）、`focus-visible` 轮廓、hover 边框与 disabled 继承。没有把所有控件做成同一尺寸：主次靠字重、底色与宽度区分。

## 5. 今天标记

- DOM：`<span class="cal-day-pill">19</span>`，1 号额外渲染 `<span class="cal-day-month">11 月</span>` 在圆外。
- 样式：`border-radius: 999px`、`min-width/height 27px`、`border 1.5px var(--accent)`、`background var(--accent-soft)`、`font-weight 700`、外圈 2px `--surface` 阴影把圆从格子里"托"出来。
- 尺寸恒定：`min-width/height` + `padding 0 6px`，两位数字也是正圆（27px），不随内容变形。
- 格子尺寸、订单定位、拖放命中区域未变（pill 在日期行内，不覆盖 lane 区）。
- 今天仍由 `localDayIndex(now, workingTimezone)` 判定，未引入任何本地时区逻辑。
- 与"选中日期"区分：当前没有选中态（点击即进详情），因此不存在混淆来源；如未来加选中，用 `.cal-day-bg` 的背景层表达，不占用圆环。

## 11. 已知问题

1. 预览条绘制在**每周底部预留带**（`bottom:3px`），不是精确落在某个 lane 上——这样不遮挡既有订单条，但离日期数字有距离；已用"预览日期格着色"补偿关联性。若要逐 lane 预览，需要改动轨道占用计算（属业务逻辑），本轮未做。
2. 月视图格子宽度有限，订单标题仍会被截断到 6–8 字（与 DEV-06D-3 一致，靠 `title` 与详情页补全）。
3. 拖动时状态区插入会使网格下移约 56px（只在拖动期间）；这是为了把反馈放在视野上方而接受的取舍。
4. `docs/assets/dev06d-3-calendar/` 下的旧截图已被本轮新图覆盖；DEV-06D-3 报告引用的是同一路径，内容为最新状态。
