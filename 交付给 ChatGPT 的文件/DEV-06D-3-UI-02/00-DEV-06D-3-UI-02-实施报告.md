## 2. CAL-UI-02 当月与非当月

**根因**：`.cal-week` 曾用 `week[3]`（该周中间那天）判断整周是否属于当月，并给整行加灰底。只要周三落在别月，整周（含属于当月的周日/周一）都被涂灰——11 月 1 日（第一行周日）与 11 月 30 日（最后一行周一）就是这样被误伤。

**修复**：删掉 `cal-week.is-outside` 与对应 CSS，只保留按格子自身 `isSameMonth(day, anchor)` 的 `data-outside`。当月格保持 `--surface`，非当月用 `--surface-alt` + 0.55 透明度，今天圆环不受影响。

实测：11/1、11/30 为当月白底；10/26–31、12/1–6 为灰蓝底（截图 01）。

## 3. CAL-UI-03 拖动状态与三段提示

**状态块不再推动网格**：`.cal-main` 设 `position: relative`，`.cal-drag-status` 改 `position:absolute; top:52px; left:12px; width:min(380px, 100%-24px); pointer-events:none; z-index:6`。

```text
拖动前 grid: top 206 / left 529 / width 809 / height 715
拖动中 grid: top 206 / left 529 / width 809 / height 715   ← 完全一致
状态块: position=absolute, pointer-events=none, 完全在视口内
```

**三段可发现性**：条内加入 `.cal-chip-handle.is-start` / `.is-end`（12px，悬停或聚焦时显示 2px 竖条 + 端部渐变底色）与 `.cal-chip-grip`（中央点阵，悬停时 0.55 透明度）。条本身 `cursor: grab`、`:active` 为 `grabbing`；`title` 追加「拖两端调整日期，拖中间整体移动」。

> 注意：本轮**无法在无头环境截到 hover 态**（见 §9），规则与结构已由 CSSOM 断言确认。

预览语义沿用上一轮：左端只改开始（交付保持）、中间整体平移（等长）、右端只改交付（开始保持）；非法落点红色预览 + 原因，不进确认框。

## 4. CAL-UI-04 防误触

- `startDrag` 记录按下坐标；`pointermove` 距离 < 6px 时**不进入拖动**（`armed=false`），预览不出现。
- 只有 `armed` 后的 `pointerup` 才置 `suppressClickRef=true`（400ms 自动清除，且下次 `pointerdown` 也会清），并打开确认框。
- 订单条点击统一走 `openOrder()`：若抑制位为真则吞掉本次 click 并复位，否则跳转。

实测（浏览器）：

```text
普通点击            → #/orders?orderId=a5      （跳转 1 次）
拖动后补发 click     → #/calendar              （跳转 0 次）
拖动取消（pointercancel）→ 无对话框、writes=0、不跳转
拖动结束后再次点击   → #/orders?orderId=a5      （恢复正常）
```

键盘路径未受影响：chip 仍是 `<button>`，Enter 走 `onOpenOrder`，`改期` 按钮独立可 Tab。

## 6. 50 单实测

| 指标 | 默认（隐藏终态） | 开启显示已结束 |
|---|---|---|
| 首屏 / 切换耗时 | 210ms（导航→首条渲染） | 12ms（勾选→双 rAF） |
| DOM 节点 | 405 | 374 |
| 月视图 chip | 9（含跨周分段） | 1 月 6 条，全部为终态 |
| +N 折叠 | 8 个（+1 ×4、+2 ×4） | 同左 |
| 未排期池 | 10 | 12（含 2 笔终态 → 历史分区） |
| 页面宽度 | 1400 = 1400 | 1400 = 1400 |
| 周视图 | 7 格，切换 26ms | — |

断言 16 条全过：50 笔载入、默认无终态、池子 10 笔、+N 出现、无横向溢出、首屏 < 2.5s、开启后终态出现且不与活动抢轨、切换 < 200ms、历史分区出现、浮层可列出且每单有改期入口、浮层在视口内、周视图 7 列、无溢出等。

**判断**：50 笔量级下 `+N` 折叠 + 终态弱化 + 「显示已结束」开关已经足够，不需要新增归档/分页/新状态。拥挤月份的真正瓶颈是**格宽**（每格约 115px，标题只能显示 6–8 字），这属于既有设计取舍，已在建议中记录。

## 7. 性能与可用性结论

- 50 笔（月视图同时可见 9 条 chip、8 个折叠入口）：渲染 210ms，交互切换 12–26ms，无可感知掉帧。
- DOM 规模 374–405 节点，无虚拟化必要。
- 开启终态后 DOM 反而更少（1 月只有终态订单），无堆积。
- 历史订单未出现重叠遮挡：轨道分配与 `+N` 仍然生效。
