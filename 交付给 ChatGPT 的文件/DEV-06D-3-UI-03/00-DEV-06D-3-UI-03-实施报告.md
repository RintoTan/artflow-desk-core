## 2. 刷新按钮

**根因**：`.cal-nav button` 与 `.cal-today` 在旧规则里显式设了 `border` + `background`，而 `.cal-refresh` 只设了高度/内边距/圆角/字号，**没有覆盖 `border` 与 `background`**，于是 WKWebView（Blink 同样）沿用 `<button>` 的原生外观——浅灰渐变 + 深色立体边框，比工具栏其它按钮更高更"凸"。

**修复**：

1. JSX 改成 `className="btn cal-refresh"`，直接复用全站按钮组件（边框/背景/hover/focus-visible/disabled 由 `.btn` 提供）。
2. CSS 只做尺寸与色调对齐：`height/min-height: var(--control-h)`、`padding: 0 12px`、`border-radius: var(--radius-sm)`、`font-size: 12.5px`、默认 `color: var(--text-muted)`、hover 换 `--surface-alt` + `--border-strong`、`:active` 下沉 1px、`:disabled` 0.55 透明度。
3. 对日历内所有按钮补 `-webkit-appearance: none; appearance: none;`，杜绝其它原生外观残留。

**只作用于 `.cal-*`**，没有全局 `button {}` 选择器，其它页面不受影响。功能未动：仍是 `onClick={() => setGeneration(n => n + 1)}`。

## 3. 日期区域

- 两列等宽：`grid-template-columns: repeat(2, minmax(0,1fr))`，`gap: 12px`，`min-width: 0` 防挤压。
- 输入统一：`appearance:none`、`display:block`、`width:100%`、`box-sizing:border-box`、`height: var(--control-h)`（34px）、`padding: 0 10px`、`border: 1px solid var(--border-strong)`、`border-radius: var(--radius-sm)`、字号 12.5、等宽数字。
- 垂直居中：`::-webkit-datetime-edit { padding: 0; line-height: 1.4 }`，日期文字不再贴顶。
- 日历图标：`::-webkit-calendar-picker-indicator { opacity: .55 }`，弱化但可点。
- disabled：`背景 --surface-alt + 虚线边框 + --text-muted + opacity:1`，文字仍可读（截图 04 右侧端点）。
- 窄视口：`@media (max-width: 560px)` 变单列，不产生横向溢出。
- 原有校验未动：`invalid` 计算、`confirmDisabled`、过去日期提示、`dropPlan` 结果回填全部保留。

## 4. 原因输入

- 标签「改期原因」+ 轻量 `选填` 徽标（11px、浅底、细边框，非彩色警告）。
- 输入与日期字段共用同一套高度/边框/圆角/字号；宽度 100%。
- `::placeholder` 用 `--text-faint`，hover 边框加深，`focus-visible` 2px 主色描边。
- 提交逻辑未动：仍是 `reason.trim()` 交给 `rescheduleInput`。

## 5. 弹窗整体

- 标题 13.5px/1.35，编号 11px 弱化，客户与类型同行排布，层级更清楚。
- 日期区、原因区、说明文字之间统一 12px；底部说明改为一条虚线分隔后的脚注。
- 非法日期与过去日期提示改成带底色的块（红 / 琥珀），比纯文字更易扫读。
- 确认/取消沿用 `ConfirmDialog` 站点规格，未改按钮尺寸与主次。
- `min-width: min(380px, 100%)`，窄屏不会被自身最小宽度顶出视口。
