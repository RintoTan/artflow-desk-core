## 2. CAL-UI-05 自由排期

**交互**：去掉单选，两个日期输入始终可编辑、可清空。

| 开始 | 交付 | 结果 |
|---|---|---|
| 空 | 空 | 确认按钮禁用（`bothEmpty`） |
| 有 | 空 | 只写开始 |
| 空 | 有 | 只写交付 |
| 有 | 有 | 两端都写；仅在两端都有值时比较先后 |

- 校验沿用原 `invalid` 计算：格式非法、`delivery < start` 仍拦截；只填一端不触发比较。
- `unchanged` 仍是「与订单当前值相同则禁用」，避免空提交。
- 未排期订单在弹窗顶部有一条说明：「可以只填一端，也可以两端都填；留空的一端不会被自动补上」。
- 拖入默认：`dropPlan(order, day, "unscheduled", "delivery")`（**dropPlan 本身未改**，只是显式传入 field），弹窗预填交付日，用户可改可清。
- 写入仍走 `rescheduleInput(order, plan, "calendar", reason)` → `update_order_details`，整单回填不变；历史事件记 old/new 两端，由既有后端逻辑完成（本轮未改）。

## 3. CAL-UI-06 独立纵向滚动

```text
.cal-main  { display:flex; flex-direction:column; max-height: calc(100dvh - 196px); overflow:hidden }
.cal-toolbar { flex: none }                  ← 工具栏固定
.cal-scroll { flex: 1 1 auto; min-height: 0; overflow: auto; overscroll-behavior: contain }
.cal-pool   { max-height: calc(100dvh - 196px); overflow: auto; overscroll-behavior: contain }
```

实测（1400×760）：

```text
before: 工具栏 top 160 / 网格 top -57 / pageY 0 / scrollTop 263
after : 工具栏 top 160 / 网格 top  63 / pageY 0 / scrollTop 143
```

滚动只发生在 `.cal-scroll` 内，工具栏与外层页面完全不动；`overscroll-behavior: contain` 阻止滚到边界后把滚动传给页面。日期格高度未压缩，月/周视图切换逻辑未改，滚轮不会切换月份。

**顺带修掉的两处抖动**（都属于"拖动期间布局不动"这条要求）：

1. 点击订单条时浏览器会聚焦按钮并滚动到可见，导致网格跳 26px → 在条与池子条目上 `onMouseDown` 阻止默认（键盘 Tab/Enter 不受影响）。
2. 原拖动状态栏替换底部提示行时，把卡片高度改了 26px → 改为固定高度 `.cal-hint-slot` 内绝对定位的浮层。

## 7. 已知问题

1. `max-height: calc(100dvh - 196px)` 是按当前页头高度估的；若后续页头改高，需要同步调整这个常量（建议改为由父级 flex 分配高度）。
2. 滚动条使用系统原生（与 SCROLLBAR-01 的 macOS 原生策略一致），Windows 上会是默认宽滚动条，未做 thin 定制。
3. 空日期字段下方仍显示「保持不变」；对"本来就没有日期"的订单略啰嗦，但保持了与已排期订单一致的文案结构。
