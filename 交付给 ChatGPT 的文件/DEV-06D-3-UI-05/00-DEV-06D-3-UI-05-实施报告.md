## 2. 关键技术实现

```text
rangeStart（某周周一） + rangeWeeks（周数）
  ├─ weeks = rangeWeeks × [7 天]，按 data-day 连续
  ├─ 每行高度恒定 → scrollTop / rowH = 周序号
  ├─ handleScroll：中心行 → visibleAnchor（月份标题、当月着色都取它）
  │                 距上下边界 < 4 行 → extend(±12 周)
  ├─ 向上补数据：prependRef = 新增行数；useLayoutEffect 里 scrollTop += 行数×rowH（视口不跳）
  ├─ scrollToDay(day)：必要时先扩范围，再一次性把该周居中（scrollTargetRef）
  └─ 上限：距今天最多各 60 周，避免 DOM 无限增长（当前最多约 120 行）
```

- 初始 `scrollTop` 在首次 `useLayoutEffect` 里设为「今天所在周居中」，因此打开即落到当月，而不是范围起点。
- 月份切换 = `scrollToDay(shiftMonth(visibleAnchor, ±1))`，不再换矩阵；不会重置订单数据或拖放状态。
- 视图切换：月→周用 `visibleAnchor` 作为周锚点；周→月把该周滚回视口。
- 滚动条：`.cal-scroll::-webkit-scrollbar { width: 0 }` + `:vertical { display: none }`，横向保留 `height: 8px`（900 视口仍能横向移动到被裁的列）。
- **没有**把 `scrollbar-width: none` 用于横向，否则窄窗会彻底失去横向可达性。

## 6. 未验证 / 已知问题

| # | 项 | 说明 |
|---|---|---|
| 1 | macOS WKWebView 实机 | NOT RUN：触控板惯性、隐藏滚动条后的手感、动态扩展时的视觉稳定性需实机确认 |
| 2 | Windows WebView2 | NOT RUN（按约定不阻塞） |
| 3 | 滚动到 ±60 周边界 | 到达上限后不再扩展，表现为"到底"；未做视觉提示 |
| 4 | 月/周切换的精确落点 | 周→月会把该周居中，可能与用户预期的"该月顶部"略有出入 |
| 5 | 远距离跳月 | 通过 `scrollToDay` 扩展范围，一次跳很远会先补若干 12 周，未做一次性大批量插入 |
| 6 | 横向滚动条 | 窄窗保留 8px 细条（纵向完全隐藏）；若产品要求横竖都不可见，需要另做拖拽/滚动方案 |
