## 一、四项问题的实际根因

### CAL-QA-02｜`+N` 在原生窗口点不动

**根因：层叠上下文，不是事件绑定。**

`.cal-day-bg[data-today="1"]` 与 `.cal-day-bg[data-outside="1"]` 都带 `opacity`（0.45 / 0.55）。
`opacity < 1` 会形成**层叠上下文**，在父级里按「定位元素、z-index:0」这一层绘制；
而 `.cal-more`（`+N`）是普通流里的行内块，没有 `position` 也没有 `z-index`，绘制在**更早的一层**。
结果：今天格与非当月格的背景被画在 `+N` 之上 —— 视觉上 `+N` 仍可见，但命中测试按绘制顺序走，
鼠标点到的是 `div.cal-day-bg`，按钮拿不到事件。

同一原因也解释了「浏览器压力测试通过、原生窗口失败」：之前的断言点的是普通（非今天、非当月）格子里的 `+N`。

两侧证据：

- Blink（`scripts/calendar-ui06-probe.mjs`）对同一个按钮做 A/B：保留修复时 `elementsFromPoint()[0] === "button.cal-more"`；
  就地撤掉 `position/z-index` 后立刻变成 `"div.cal-day-bg"`（该断言在 3 档尺寸全绿）。
- 原生 WKWebView：修复前，真实鼠标点击今天格 `+N` 的中心，DOM 收到的是
  `pointerdown/mousedown/mouseup/click` 全部落在 `DIV.cal-day-bg`。

次要成因（一并修掉）：`+N` 浮层按 `min(rect.bottom, innerHeight-328)` 定位，窗口较矮时会被夹到按钮**上方并盖住按钮**，
于是「再点同一个 `+N` 关闭」实际点在浮层里，表现为「点了没反应」。

### CAL-UI-07｜未排期订单拖入被拒

**根因：`dropPlan()` 收到 `mode="unscheduled"` 却没有 `field`。**
`src/lib/calendar.ts` 对这种情况返回 `{ok:false, reason:"请选择写入计划开始日期还是计划交付日期"}`。
UI-04 曾在 `move` 里传过 `"delivery"`，UI-05 重写连续日历后该参数丢失，只剩 `dropPlan(order, day, mode)`。

### CAL-UI-08｜月视图自适应

**根因：行高是写死的。** `CalendarGrid` 用内联 `gridTemplateRows: auto repeat(3, 22px) 18px`，
与可视高度无关；且视口高度的测量 `useLayoutEffect` 依赖数组为 `[]`，而首次渲染时还在「正在读取订单」分支，
`.cal-scroll` 尚未挂载 → `el === null` 直接返回，之后永不重跑，`viewportH` 恒为 0。

### CAL-UI-09｜月份高亮与非当月交互

**根因：`visibleAnchor` 取的是「视口中心那一行的星期三」。**
跨月那一周（如 11-30～12-06）的星期三是 12-02，于是标题与整屏高亮会提前一个月跳过去；
同时日期格根本没有 `onClick`，「点击非当月日期更新焦点与月份」无从发生。

## 四、macOS 原生 Tauri 窗口验证

### 4.1 如何解决「无法投递真实鼠标事件」

本机硬约束（已实测，非推断）：

- `AXIsProcessTrusted = false`，`CGPreflightPostEventAccess() = false`
- `osascript` 报 `-1719 不允许辅助访问`
- `DYLD_INSERT_LIBRARY` 被 SIP 剥离（连 `/bin/echo` 都不生效，`DYLD_PRINT_LIBRARIES` 也无输出）
- 无 `tauri-driver`（Tauri v2 在 macOS 上不支持 WebDriver）

可行路径（已验证）：**lldb 附着 + `dlopen` 注入**。

```
lldb -p <pid> -o 'expr (void*)dlopen("/tmp/afctl/afctl.dylib", 2)' -o detach -o quit
```

注入的 `afctl` 在应用进程内用 `CGEventCreateMouseEvent` 造事件、包成 `NSEvent`、`[win sendEvent:]` 投递。
两个必须踩准的点（否则"点了没反应"）：

1. `[NSEvent eventWithCGEvent:]` 生成的 `windowNumber` 恒为 0，`[NSApp sendEvent:]` 无法路由 → 必须 `[win sendEvent:]`；
2. AppKit 会把 CG 点按「全局左上角」换算成 `locationInWindow`（实测 `locationInWindow.y === 屏幕高 - cgY`），
   所以 CG 点要写成 `(winX, screenH - winY)`；`winY` 用 `innerHeight - cssY`（`contentLayoutRect` 比它多出标题栏那 32pt）。

**事件性质说明**：事件是合成出来的（不是物理鼠标），但走的是真实 AppKit → 真实 `WKWebView` 命中测试 → 真实 DOM 派发，
不是 `element.click()` / `dispatchEvent()`。截图来自 `screencapture -l <windowNumber>`。
