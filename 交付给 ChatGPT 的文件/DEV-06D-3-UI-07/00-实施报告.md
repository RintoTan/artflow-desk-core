## 一、三个问题的实际根因

### CAL-UI-10｜月/周切换是系统灰按钮

**根因：样式选择器根本没命中。**

`CalendarPage` 里写的是 `<div className="segmented cal-views"><button aria-pressed=…>`，
而全站分段控件的样式是 `.segmented .btn` / `.segmented .btn[aria-pressed="true"]`——
这两个按钮**没有 `.btn` 类**，所以容器样式生效、**选中态规则一条都没匹配上**，
按钮退回浏览器默认外观：灰底、灰边、没有选中反馈。看起来就像系统原生按钮。

顺带确认：`.segmented` 自身的 `gap/padding/border/background` 是生效的，所以"外壳像分段控件、里面是灰按钮"。

### CAL-UI-11｜轨道数写死、空间利用粗糙

**根因：轨道数是三档阈值，不是算出来的。**

```ts
const lanes = rowH >= 96 ? Math.min(preferredLanes, 3) : rowH >= 66 ? Math.min(preferredLanes, 2) : 1;
```

- 上限永远是 3：1420×1000 的行高 120px 明明能放 4 条，也只给 3 条；
- 降级靠 96/66 两个魔法阈值，和真实内容尺寸（条高、间距、数字行、折叠行）没有关系；
- 日期行与折叠行按 0.24/0.16 固定比例分配，大窗口下这部分被白白放大，挤掉了本该给轨道的空间。

### CAL-UI-12｜拖拽预览错位

**根因：预览条贴的是"周行底部"，不是"订单轨道"。**

```css
.cal-preview { position: absolute; bottom: 3px; height: 18px; }
```

- UI-06 把行高做成 46~120px 可变之后，`bottom: 3px` 意味着预览条永远贴在**整行最下沿**：
  行越高，条离鼠标越远；行越矮（46px），条直接压到 `+N` 行和下一行的日期数字上——
  看起来就是"预览跑到别的日期格""和鼠标对不上"。
- 预览高度写死 18px，不随 chip 变化，小窗下会盖住 `+N`。
- 同一区间被两种视觉同时表达：`.cal-preview` 细条 + `.cal-day-bg[data-preview]` 的**整格蓝底**，
  看起来像"两个不一致的预览"。
- 追加发现：连续缩放时按"行序号"补偿 `scrollTop`，月份周数在 5/6 之间变化会让行高反复变，
  视口会一路漂（实测 1400×1000 缩放六次后跳到 2025 年 12 月），拖动过程中同样表现为"预览乱跳"。
