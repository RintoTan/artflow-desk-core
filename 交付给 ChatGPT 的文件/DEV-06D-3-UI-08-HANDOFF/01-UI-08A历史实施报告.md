## 一、根因

### 1. +N 挤在底部、越界、位置不统一

`+N` 被放在**独立的最后一行**（`gridRow: laneCount + 2`），而这一行的高度由 `moreH` 决定：
UI-08 时 `moreH` 最小只有 14px，胶囊却固定 16px —— **胶囊比行高还高 2px**，所以看起来"贴边、溢出、压到下周"。

更麻烦的是这一行在**不同周里行号不同**（随 `laneCount` 变化），视觉上就成了"位置不统一"。

### 2. 字号跟着行高缩

```css
.cal-day-num { font-size: min(11.5px, calc(var(--cal-num-h, 32px) * 0.42)); }
```

外加 `fontPx = clamp(9, (chipH - 4) * 0.7, 10.5)`：行高一小，日期和订单标题一起掉到 8.5~9px。
这是"为了塞下布局而牺牲可读性"，正是本轮要解除的耦合。

## 二、改动

| 文件 | 改动 |
| --- | --- |
| `src/lib/calendar.ts` | `metricsFromRow` 新增 `moreRow` 参数：`+N` 在顶部时不占独立行（`moreH = 0`），省下的高度全给订单轨道；底部槽位时 `moreH = 20~22`（16px 胶囊 + 4px 边距）；**字号固定 `fontPx = 11.5`**，不再由 `chipH` 推导；补三段求和超预算的兜底 |
| `src/components/CalendarGrid.tsx` | 新增 `topMore` prop：`+N` 在顶部时 `gridRow: 1` + `data-slot="top"`，底部时 `gridRow: laneCount + 2` + `data-slot="bottom"` |
| `src/pages/CalendarPage.tsx` | 跟踪 `viewportW`，用**实际格宽** `floor((clientWidth-2)/7)` 判定：`≥ 46px` 走右上角，否则回退底部（阈值 = 6px 内边距 + 两位日期 + 间距 + 20px 胶囊 + 4px 右边距） |
| `src/styles.css` | 日期数字 12px、订单 11.5px、`+N` 11px；`+N` 改胶囊（淡蓝底、深蓝灰字、圆角 999、无重描边、hover 变色）；顶部槽位 `margin-right: 4px`、底部槽位 `margin: 0 4px 4px` |
| `scripts/calendar-fit-probe.mjs` | 新增 5 条断言：字号实测、+N 不溢出、不与订单条重叠、边界留白 ≥4px、位置随格宽切换；支持 `FIT_DENSE=N` 造同日 N 笔 |

未改：数据库/迁移/后端日期写入/滚动与定位逻辑/订单日期语义/轨道分配规则。
