# 02 · UI-08 剩余项实施报告

基线 `f83bbc9`（UI-08A 报告），本轮代码提交见 `03-测试与验收报告.md` 末尾。

## 一、根因

### 1. 订单"丢失"（CAL-UI-13）
用真实 QA 库（`~/Library/Application Support/dev.artflow.minidesk.qa/seeded`，active gen `gen-662c45c3…`）逐项核对：

- `AF-2026-0012` 的 `planned_delivery_date` 已写成 `2026-11-09`，`revision = 1`，日历 DOM 里 `[data-order-id="1e3c8674-…"]` 命中。
- 全量对账 10 笔活动订单：`present 9 / missing 1`，缺的是 `AF-2026-0013`（两端日期皆空，本就不该进网格，就在未排期区）。
- UI-07/UI-08A 报告里"改期后条数 0"来自脚本用**订单编号**匹配 `data-order-id`（那里存 UUID），恒为 0。

结论：属于任务书的 **E 类**（数据正常，只是不在网格/可视范围），**不是 A/B/C/D**。刷新按钮走 `generation → useEffect → api.listOrders()`，是真实重新拉取，不是重渲染。

### 2. 连续滚动"卡段"（CAL-UI-15）
```ts
if (todayWeek - nextStart > MAX_BACK_WEEKS * 7) return;   // ±60 周直接拒绝扩展
```
滚到 ±60 周后列表不再增长 → 触底 → 用户感到人为边界。

### 3. 月份标题错误（同上）
`handleScroll` 用 `scrollTop ÷ rowH` 反推行号，再乘回 `rangeStart`。行高会随月份周数变化、窗口还会补行/裁行，
一旦用的是旧的 `rangeStart`，整段就偏掉（实测标题停在 2026 年 8 月、视口在 11 月）。

### 4. 左侧只有未排期池
`CalendarPage` 只渲染了一个 `.cal-pool`，分类与定位能力都不存在。

## 三、关键链路

- **改期回显**：`RescheduleDialog → rescheduleInput() → update_order_details（revision 乐观锁 + 同事务写 rescheduled 事件）→ confirmReschedule 成功后 setGeneration+1 → 重新 listOrders → 重算 span/轨道 → DOM 重渲染`。
- **刷新**：按钮只做 `setGeneration(n+1)`，真实的 `api.status()` + `api.listOrders()` 在 effect 里跑，失败写 `refreshError`。
- **月份焦点**：取 `.cal-week[data-start]`，只统计与滚动容器重叠 ≥50% 的行，每行投给它 7 天里占多数的月份，得票最多者胜；`visibleAnchor` 只反映视口，不反向控制滚动。
- **定位聚焦**：已排期 → `scrollToDay(span.from)`（不在窗口内会先扩范围）+ `focusOrderId`；未排期/无历史日期完成单 → 展开分区 + `scrollIntoView` + 1.8s `is-flash`；终态有历史日期 → 临时打开"显示已结束"再定位。
