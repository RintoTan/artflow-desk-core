# 01 · 实施报告

## 一、远端定位失败的真实根因

`scrollToDay()` 本身没问题（会扩范围、会设目标），问题在**下一帧**：

```
layout effect:
  prev = lastFrameRef.current            // 跳转前的中心日（比如 11 月）
  el.scrollTop = index * rowH - clientH/2  // 跳到 2027-08 ✓
  scrollTargetRef = null                 // 但 lastFrameRef 没更新
下一次 render（setVisibleAnchor 触发）:
  measured 变了（月周数 6→5）
  heightChanged = true 且 scrollTargetRef 已是 null
  → 走"把视口中心那一天钉回原位"的补偿分支，用的是 prev.centerDay = 11 月
  → scrollTop 被拉回 11 月
```

所以"等 900ms 后检查"看到的就是：标题 11 月、目标 `inView=false`。

**修复**：跳转后立刻重写 `lastFrameRef`（`centerDay = 目标日`）并置 `jumpRef`，让下一帧跳过补偿；
同时记录 `jumpAnchorRef`（目标日 + 时间戳），紧接的行高变化改为围绕**目标日**重新居中；
滚动事件在跳转后 1.5s 内不覆盖 `visibleAnchor`（避免多数票把标题盖回去）。

## 二、连续滚动

- 滚动处理改 `requestAnimationFrame` 合并，一帧最多算一次。
- 月份归属完全按 DOM：`.cal-week[data-start]` + 与滚动容器重叠 ≥50% 的行，每行投给它 7 天里占多数的月份；不再用 `scrollTop ÷ 行高` 反推（那是"标题停在 8 月"的根因）。
- 窗口上限 104 周，到顶裁另一端（`trimHeadRef` 按 12 行回退 `scrollTop`），用户感知不到硬边界。
- 缩放锚点：按"视口中心那一天"而非行序号补偿。

## 三、定位居中算法

```
targetWeek = weekStartOf(span.from ?? span.to)
index      = (targetWeek - rangeStart) / 7
scrollTop  = index * rowH - clientH / 2 + rowH / 2
```

以 `.cal-scroll` 的可滚动高度为基准（已排除工具栏与底部说明），跳转后若行高变化，按 `jumpAnchorRef` 重新居中一次。
长区间订单只用开始日期所在行居中，保证订单主体在视口内，不为"数学居中"把它挤出屏幕。

## 四、A+B 3 秒自动解除

- `startFocus(id)`：清旧定时器 → 设 `focusOrderId` → 等两帧（跳转已发生）后 `setTimeout(3000)` 清除。
- 计时从"定位完成"起算，不因滚动/重渲染重置（定时器存在 ref 里）。
- 连续点不同图钉：先清旧定时器再设新的，不会出现旧定时器误清新聚焦。
- 手动取消仍保留：再点同一图钉 / Esc / 点日期格 / 切视图。

## 五、未排期图钉提示

`OrderRail` 内部状态 `hint {text,x,y}`，用 `position: fixed` 贴在图钉右下（并夹在视口内），
2.4s 自动消失，不打开详情、不改日期、不动日历；活动未排期 → 「该订单尚未排期，无法定位到日历日期」，
完成无日期 → 「该完成订单未参与排期」。

## 六、完成单图钉列对齐

卡片改成固定四列 `14px minmax(0,1fr) auto 22px`（手柄 / 主体 / 改期 / 图钉），
完成单不渲染手柄与改期按钮，但**空列占位保留**，图钉右边缘在所有卡片上完全一致（探针断言 `uniq.length === 1`）。

## 七、周视图三行

`weekGridMetrics(availableHeight)`：日期行 26 + 至少 3 条轨道 + 折叠行 20，行高按可用高度在 122~280 之间拉长，
轨道高 ≥18、条高 14~19、字号固定 11.5。原生 1400×1000 实测 6 轨 × 39px、行高 280。
