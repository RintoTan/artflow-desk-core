# 01 · 实施报告

## 一、首次进入日历没有订单

### 根因
首次"把视口对准今天"的判断写在每帧都跑的大 layout effect 里，条件是：

```ts
const target = scrollTargetRef.current ??
  (initializedRef.current || today === null || viewportH === 0 ? null : today);
```

挂载那一帧 `viewportH` 还是 0（`.cal-scroll` 的可视高度要等 ResizeObserver 回调），
于是 `target === null` 整段跳过；`initializedRef` 没被置位，下一帧虽然 `viewportH` 有了值，
但那段代码同时要求 `rangeStart !== null`（OK）——真正的问题是**它被后面新增的"行高/视口变化补偿"分支提前 return 掉了**，
补偿分支用 `lastFrameRef.current`（此时为 null 或旧值）直接退出，初始化永远轮不到。

结果：`scrollTop = 0`，日历停在 29 周窗口的**最顶部（2026 年 8 月）**，那里没有订单；
标题却按 `anchor`（今天）显示"2026 年 11 月"。看起来就是"日历是空的 / 订单不显示"。

### 修复
`src/pages/CalendarPage.tsx` 新增独立的初始化 effect（依赖 `today / rangeStart / viewportH`）：

```ts
useLayoutEffect(() => {
  if (initializedRef.current || today === null || rangeStart === null || viewportH === 0) return;
  const index = Math.round((weekStartOf(today) - rangeStart) / 7);
  el.scrollTop = Math.max(0, index * rowH - el.clientHeight / 2 + rowH / 2);
  initializedRef.current = true;
  lastFrameRef.current = { rowH, clientH: el.clientHeight, scrollTop: el.scrollTop, centerDay: today };
  setVisibleAnchor(today);
}, [today, rangeStart, viewportH]);
```

它与"缩放补偿"彻底解耦：只要数据、窗口起点、可视高度三者就绪就一定会执行一次。

### 原生验证
重启 QA 应用后立即进入日历，按 350ms 间隔采样：

```
dt=75ms   title=2026 年 11 月  chips=22  scrollTop=861  (sh=2202, h=453)
dt=490ms  同上
…         稳定
```

修复前同一时刻是 `chips=22` 但 `scrollTop=0`、可见月份是 8 月。

## 二、原生连续滚动

### 真实滚动容器（实测）
```
.cal-scroll  clientHeight=693  scrollHeight=10173  overflow:auto  overscroll-behavior:contain
```
容器本身可滚动（`scrollHeight ≫ clientHeight`），页面层 `.main.main-fixed` 是 `overflow:hidden`，
没有第二个滚动容器抢事件；全项目只有 `ImageViewer` 注册了 `wheel`，日历没有任何 `wheel/touchmove` 拦截。

### 为什么用户"翻不出本月"
主因就是第一节：初始位置在 **8 月**，而标题写着 **11 月**。滚轮是在动的，但起点错了 3 个月，
且标题不同步，给人的感觉是"滚不动 / 只能按月份箭头"。

### 其他加固
- 滚动处理 `requestAnimationFrame` 合并（一帧最多一次计算）。
- 月份归属按 `.cal-week[data-start]` + 与视口重叠 ≥50% 的行投票，不再用 `scrollTop ÷ 行高` 反推。
- 窗口上限 104 周，到顶裁另一端并补偿 `scrollTop`（`trimHeadRef`）。
- 周视图固定 3 行，`extendWeeks` 直接跳过，避免误扩。

### 未完成
**真实滚轮 / 触控板仍未在本机自动化验收**：afctl 用 `CGEventCreateScrollWheelEvent` 造的 NSEvent
没有窗口归属，`[win sendEvent:]` 到不了 `WKScrollView`（实测连续 40 次滚动 `scrollTop` 不变）。
按规则标记 **NOT RUN**，不冒充 PASS。

## 三、周视图 3×7

- `weeks`：`view === "week"` 时返回 `[-1, 0, 1]` 三行（`weekStartOf(anchor)` 为基准，周一起始）。
- `weekGridMetrics(availableHeight, rows = 3)`：先按 3 行均分可视高度，再决定轨道数与轨道高；
  轨道优先"少而厚"（≥22px），空间紧张时保底 3 条（最小 17px）。
- 上一段 / 下一段整体平移一周；今天把当前周放到中间行；点日期更新焦点但不改变三行范围。
- 月视图的 104 周窗口、行高、+N、动态轨道完全未改。

| 窗口 | 行数 | 轨道 | 轨道高 | 行高 | 三行总高 | 可视高 | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1400×1000 | 3 | 6 | 30 | 227 | 680 | 693 | 全可见 |
| 1400×760 | 3 | 4 | 26 | 151 | 452 | 453 | 全可见 |
| 1120×760 | 3 | 4 | 26 | 151 | 452 | 453 | 全可见 |
| 900×760 | 3 | 4 | 24 | 143 | 428 | 436 | 全可见 |
