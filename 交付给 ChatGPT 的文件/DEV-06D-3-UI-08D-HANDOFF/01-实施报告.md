# 01 · 实施报告

## 一、滚动"卡住"的真实根因（月 + 周通用）

```ts
function handleScroll() {
  if (scrollFrameRef.current !== null) return;
  scrollFrameRef.current = requestAnimationFrame(() => { scrollFrameRef.current = null; applyScrollState(); });
}
```

`requestAnimationFrame` 在 WKWebView 里，**窗口被其它应用遮挡或不可见时会被节流甚至完全不派发**。
一旦第一次 `rAF` 没有回调，`scrollFrameRef` 就永久停在非 null，之后每一次 `scroll` 都在第一行 return ——
表现为：滚动位置能动，但**日期窗口不再扩展、月份标题不再更新、滚动到边界就"卡住"**。

证据（原生窗口）：滚轮连滚 8 次，`scrollTop` 在变（1606 → 1706），但 `.cal-week` 恒为 29 行、标题不动。

### 修复
1. 合并机制改成 `setTimeout(…, 16)`：不依赖 rAF 的可见性节流，回调一定会来。
2. 扩展触发不再依赖 `rowHRef`（某些帧还是 0），改为按真实滚动位置：
   `scrollTop <= guard` → 向上补；`scrollTop + clientHeight >= scrollHeight - guard` → 向下补，
   `guard = max(200, rowH * 3)`。

修复后实测（原生）：滚到顶 → **29 行变 53 行**，首行从 `2026-08-10` 前移到 `2026-02-23`，
`scrollTop` 被补偿到 1104（视口内容不跳）；滚到底 → **65 行**，无重复、无缺失。

## 二、周视图连续滚动

UI-08C 里 `weeks` 对周视图返回 `[-1,0,1]`（写死三周），`extendWeeks` 又跳过周视图 ——
数据本身只有三周，当然滚不出更多。

### 修复
- `weeks` 统一由 `rangeStart / rangeWeeks` 生成，周视图不再特判；
- 周视图的差异只剩"一屏露 3 行"（`weekGridMetrics(viewportH, 3)` 决定行高）；
- `extendWeeks` 不再跳过周视图；
- 周视图标题跟随**视口正中那一行**所在的周（`applyScrollState` 里单独分支）；
- 上一段 / 下一段：`scrollToDay(weekStart ± 7)`，焦点周与滚动位置一起移动；
- 定位（图钉）在周视图里也走 `scrollToDay`，不再只改 `anchor`。

## 三、原生滚轮验收方式的修正

此前 `CGEventCreateScrollWheelEvent` 造的 NSEvent 投不进 `WKScrollView`，原因是**投递方式**错了：
`[NSEvent eventWithCGEvent:]` 生成的 `windowNumber` 恒为 0，`[NSApp sendEvent:]` 无法路由。
和当初鼠标事件一样，改成 `[win sendEvent:]` 并把 CG 点按 `screenH - y` 反算即可。

实测：`{"op":"wheel","x":800,"y":400,"dy":-300}` 连续投递后 `scrollTop` 由 1306 变到 1606/1706，
日历真的滚动了。**这是真实 AppKit 滚轮事件经 WebKit 命中测试后的滚动**，但它仍是合成事件，
所以只有"滚轮机制可用"可以记 PASS，"物理鼠标/触控板手感"仍需人工确认。

## 四、搜索框两个 X

`input[type="search"]` 在 WebKit 里自带 `::-webkit-search-cancel-button`，
我们另外渲染了带 `aria-label` 的 `.cal-rail-clear` → 两个 X 并排。

修复：只关掉**原生**那个（`appearance: none; display: none`），保留自定义按钮。
实测：`document.querySelectorAll(".cal-rail-clear").length === 1`。
