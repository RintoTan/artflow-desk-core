# 01 · 实施报告

## 一、周视图「今天」定位失效（P0）

### 根因
```tsx
onClick={() => {
  setAnchor(today);
  setFocusedDay(today);
  if (view === "month") scrollToDay(today);
  else setAnchor(today);        // ← 周视图只改锚点，滚动位置纹丝不动
}}
```
周视图的网格是「104 周连续窗口 + 一屏露 3 行」，只改 `anchor` 不会改变 `scrollTop`，
于是网格停在原处：今天所在周落在第一行，而标题按 `visibleAnchor`（中间行）显示 11-23 ~ 11-29 ——
与用户截图完全一致。

### 修复
- 今天按钮：两种视图统一 `scrollToDay(today)`。
- 周视图跳转改为**按整行对齐**：`scrollTop = (index - 1) * rowH`，
  保证「前一周 / 本周 / 后一周」三行对应可视区的上中下三行；
  月视图仍用像素居中（`index*rowH - clientH/2 + rowH/2`）。
- `weekGridMetrics` 增加三段之和 ≤ 单行预算的收敛（`while … laneH--`）：
  之前 26+4×… 会超出预算 4px，导致第三行被裁掉。

### 实测（原生，1400×1000）
```
滚到 2027-04 后点「今天」：
  title = 2026-11-16 ~ 2026-11-22
  可视行 = 2026-11-09 / 2026-11-16（今天在内）……
```
今天所在周已经是可视区第二行、标题与之一致；**但第三行仍有约半行被裁**（gapBottom 112px），
未做到「三行都完整且今天正中」→ 记 **PARTIAL**，原因尚未定位完。

## 二、连续滚动卡住（P0）

UI-08D 已把合并机制从 rAF 改成 setTimeout（rAF 在窗口被遮挡时不派发，标志位会永久卡住）。
本轮继续把扩展触发改成按真实滚动位置（`scrollTop <= guard` / 到底余量 `<= guard`），
并把 `rowH` 依赖去掉（某些帧 rowH 还是 0，会让扩展永不触发）。

### 原生实测（AppKit 合成滚轮 → `[win sendEvent:]` → WKScrollView）
| 阶段 | scrollTop | 周行数 | 首行 | 标题 |
| --- | --- | --- | --- | --- |
| 初始 | 1306 | 29 | 2026-08-10 | 2026 年 11 月 |
| 下滚 30 次 | 2577 | 41 | 2026-08-10 | 2027 年 1 月 |
| 继续下滚 | — | 53 | 2026-05-18 | 2026 年 9 月（反向验证） |
| 深度下滚 40 次 | 20393 | 101 | 2026-02-23 | 2027-11-22 ~ 2027-11-28 |

- 每次扩展都伴随 `scrollTop` 补偿，视口内容不跳；
- 日期序列 **无重复、无缺失**（`dup 0 / gap 0`）；
- 到 104 周上限后靠裁剪另一端继续前进，未出现「墙」。

## 三、原生滚轮验收方式的说明

`CGEventCreateScrollWheelEvent` 造的 NSEvent **没有窗口号**（`windowNumber == 0`），
`[NSApp sendEvent:]` 无法路由 → 这是 UI-08D 之前"滚轮投不进去"的真因。
改成 `[win sendEvent:]` + CG 点按 `screenH - y` 反算后，滚动真实生效（`scrollTop` 1306→1606→1706…）。

**定性**：这是真实 AppKit 滚轮事件、经过 WebKit 命中测试后的原生滚动，
但仍是程序合成，不是物理鼠标/触控板 → 触控板与手感一律 **NOT RUN**。
