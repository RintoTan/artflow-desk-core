# 01 · 实施报告

基线 `ca0cdd0`｜**采用方案 A**（局部但结构性修复），未进入方案 B。

## 一、根因（审计已证）+ 本轮新增发现

审计确认的主因：**月视图行高依赖可见月份** → 跨月时行高 114↔136 变化 → layout effect 的"保持视口中心日"补偿用**上一帧**的中心日重算 scrollTop → 把视口拉回旧月份，并自我维持。

本轮在实施过程中又抓到第二个根因（此前从未被记录）：

**窗口滑动用的是"固定像素补偿"，与浏览器自身的滚动调整叠加成二次补偿。**
`extendWeeks` 到 104 周上限后 `setRangeStart(+12 周)` 并 `scrollTop -= 12*rowH`：
DOM 头部一次性少掉 12 行，浏览器已经把滚动位置调整过一次，再减一次等于**多退 12 周**。
原生采样里出现的 `maxBack = 84 天`（正好 12 周）就是它。

## 二、方案 A 的三处改动

### A1 月视图固定 6 周预算
```ts
- monthGridMetrics(viewportH, weeksInMonth(monthAnchor), !topMore)
+ monthGridMetrics(viewportH, 6, !topMore)
```
行高只由视口高度决定，跨月/跨年不再改行高。5 周月份底部多一行空白，是连续日历的合理代价。

### A2 删除两个竞争性自动居中
- 删除 layout effect 中 "heightChanged || viewportChanged → 按 prev.centerDay 重居中" 分支；
- 删除 `jumpAnchorRef`（1.5s 跟随重居中）及 `jumpRef`；
- `applyScrollState` 里那套"跳转后 1.5s 冻结标题"随之移除。

### A3 保留必要补偿（并改成日期锚点）
保留：今天按钮 / 图钉定位 / 视图切换的显式跳转、窗口滑动补偿。
但**窗口滑动补偿从"±n×rowH"改成"按视口顶部那一天"**：

```ts
captureRangeShift();                 // 记录 { day: 顶部行起始日, offset: 行内偏移 }
setRangeStart(...); setRangeWeeks(...);
// 渲染后：
index = (weekStartOf(day) - rangeStart) / 7;
el.scrollTop = index * rowH + offset;
```
配合 CSS `overflow-anchor: none`，让"谁负责补偿"只有一个主人。

### A4 容器尺寸变化单独处理
新增一个只依赖 `viewportH` 的 layout effect：真正 resize 时按 `lastFrameRef.centerDay` 把中心日钉回原位；
因为行高不再随月份变化，这个 effect 不会被滚动或跨月误触发。
