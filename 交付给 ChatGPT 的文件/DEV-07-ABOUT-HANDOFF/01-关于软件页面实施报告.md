## 二、数据环境入口如何合并

原 `StatusPage` 提供的全部内容逐项核对后迁入 AboutPage 的「数据环境」区块：

| 原内容 | 现状 |
| --- | --- |
| 首次启动 / 已连接提示 | 保留（标题下副文案） |
| 完整性 badge | 保留（`integrity === "ok"` → 绿色「正常」） |
| 运行模式（正式 / QA + 场景） | 保留，QA 文案不变 |
| 应用版本 / 数据库结构 / 数据代际 | 保留 |
| SQLite 版本 / 日志模式 / 写入锁 | 保留 |
| 工作时区 / 系统时区 | 保留 |
| 数据目录（绝对路径） | 保留（等宽块） |
| 当前数据 5 项统计 | 保留（同一组 `stat-row-metrics`） |
| 编号高水位表（年份 / 最大序号 / 下一编号） | 保留（无数据时同样只显示一句说明） |
| 读取失败提示 + 「应用已停止写入」 | 保留，并额外保证此时不显示任何环境结论 |

原页面**没有**操作按钮（纯展示），因此不存在"功能入口丢失"；本轮也没有新增按钮。

QA 标识从一处增加到两处：面板头部 `QA 测试环境` badge + 环境区内的隔离说明条，避免滚动后丢失上下文。

## 三、运行模式判定

- 唯一来源是后端 `status` 命令返回的 `qaMode` / `qaScenario`（由 Rust 按真实 identifier 与数据根判定）；
- 前端没有根据窗口标题、路由或环境变量猜测；
- 查询失败时：环境区显示「无法读取数据环境」+ 原始错误，**不显示**「正式应用」或任何环境结论，badge 也不渲染。

## 四、版本号来源

| 位置 | 值 | 说明 |
| --- | --- | --- |
| `package.json` | `0.1.0` | 前端包版本 |
| `src-tauri/Cargo.toml` | `0.1.0` | Rust crate 版本 |
| `src-tauri/tauri.conf.json` | `0.1.0` | 打包版本 |
| 界面显示 | `env!("CARGO_PKG_VERSION")` → `status.appVersion` | 三者一致，界面直接显示后端读到的值 |

页面里**没有**写死版本字符串；测试用 `appVersion: "9.9.9"` 反证过这一点。
构建类型（正式 / QA 预置 / QA 空白）来自 `qaMode` + `qaScenario`，没有伪造构建时间或 Git SHA。

## 五、布局

- 沿用设置页的面板结构（`section.panel` + `panel-head`），浅色卡片、深色文字、强调色 badge；
- 模块卡 `repeat(auto-fit, minmax(260px,1fr))`，窄窗自动单列（900px / 530px 断点下为单列）；
- 指引用原生 `<details>`，键盘可操作，无自定义 JS 状态；
- 深色主题下复用既有 CSS 变量，没有新增强调色硬编码。
