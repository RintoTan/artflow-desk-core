## 二、构建过程的两个实际发现

### 1. 打包会把三个开发用 CLI 一起塞进 MacOS/

首轮 `ArtFlow Desk Core.app` 的 `Contents/MacOS/` 里有 4 个可执行文件：

```
artflow-minidesk  attachments-probe  minidesk-probe  qa_seed
```

它们来自 `src-tauri/src/bin/`（`[[bin]]` 目标 + 自动发现），tauri-bundler 会把 crate 的全部可执行目标复制进 bundle。

处理：构建后删除这三个非交付可执行文件，并重新 ad-hoc 签名：

```bash
rm -f ".../Contents/MacOS/{attachments-probe,minidesk-probe,qa_seed}"
codesign --force --sign - "ArtFlow Desk Core.app"
codesign --verify --deep --strict "ArtFlow Desk Core.app"   # → 通过
```

结果：34 MiB → **21 MiB**，`MacOS/` 只剩 `artflow-minidesk`。

> 没有用 `required-features` 把这三个 bin 关掉：`tests/lock.rs`、`tests/numbering.rs`、`tests/attachments_recovery.rs`
> 用 `env!("CARGO_BIN_EXE_…")` 引用它们，关掉会让 `cargo test` 直接编译失败。
> 长期方案建议放到 DEV-08-FINISH 讨论（拆独立 crate 或纳入 bundler 排除规则）。

### 2. 打包后 `fetch("asset://…")` 会被 CSP 拦掉

release 的 CSP 是：

```
default-src 'self'; img-src 'self' blob: data: asset: http://asset.localhost; style-src 'self' 'unsafe-inline'
```

没有 `connect-src`，因此 `fetch` 回落到 `default-src 'self'` → `asset:` 请求在 JS 层直接拒绝。
**这意味着打包环境不能像开发环境那样用 `fetch` 读状态码做安全测试**，必须改用 `<img>` 解码结果判定（见 `02` 报告）。
这不是缺陷，是 CSP 的正确行为；但它让"开发环境 PASS ⇒ 打包环境 PASS"的类推失效，必须实测。
